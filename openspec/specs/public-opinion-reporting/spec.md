# public-opinion-reporting Specification

## Purpose

定义基于锁定正常原创帖快照生成异步舆情报告的边界，包括版本化结果、数据质量、受控来源追溯与 Word 导出。
## Requirements
### Requirement: 锁定范围的异步舆情报告
系统 SHALL 允许已认证运营人员为一个可管理游戏和上海时区日期范围创建 `PUBLIC_OPINION_REPORT`。创建时 SHALL 固定 `source_appid`、起止日期、`status=2` 正常帖规则、报告算法版本和模板版本；默认范围为最近 30 天，范围 MUST 为 1 至 90 天。任务只可分析范围内的 `OriginalPost`，不得读取候选转发帖、待判定帖、非正常状态原创帖、评论正文或上游数据。

首次实际执行时，系统 SHALL 锁定精确的来源成员；锁定后该报告的自动重试和人工重跑 MUST 使用相同成员，即使原帖随后被删除、编辑、变为非正常状态，或范围内新增帖子。系统 SHALL 使用稳定 Report、来源清单和 Run 版本表示该关系，不得用可覆盖的单一结果记录代替。

同一游戏、范围和算法版本在存在待执行或执行中的 Run 时 SHALL 返回既有 Report 与 Run；系统 MUST 使用既有 `BackgroundJob.active_coalescing_key` 的数据库唯一约束在并发提交下保证该约束。每个 Run SHALL 一对一关联其 Job。已完成或失败的 Run 不得被覆盖；运营人员重新生成 SHALL 在同一已锁定 Report 下创建新的 Run 与 Job，不得重新选源。

#### Scenario: 首次执行锁定 400 帖
- **WHEN** 报告的首次 Worker 执行按范围选中 400 篇正常原创帖
- **THEN** 系统 SHALL 将这 400 个成员、稳定排序键及分析所需内容/AI 快照原子锁定为来源清单
- **THEN** 后续重试或重跑不得因状态、内容、AI 或日期范围数据变化加入、移除或替换任何成员

#### Scenario: 创建默认范围报告
- **WHEN** 运营人员在当前可管理游戏中未修改日期范围而创建报告
- **THEN** 系统 SHALL 创建或复用最近 30 天正常原创帖的本地后台任务
- **THEN** HTTP 请求不得建立 CDP 会话、请求上游、执行审核或写操作

#### Scenario: 拒绝无效范围
- **WHEN** 运营人员提交超过 90 天、开始日晚于结束日、没有可管理游戏或创建前帖子数超过受限上限的范围
- **THEN** 系统 SHALL 拒绝创建任务并返回固定可处理原因
- **THEN** 系统不得创建部分报告、后台任务或 Word 文件

#### Scenario: 并发提交相同范围
- **WHEN** 两个创建请求同时提交相同游戏、日期范围和算法版本
- **THEN** 系统 SHALL 只持久化一份活跃 Run、一个关联 Job 和一个稳定 Report
- **THEN** 两个请求均不得因并发冲突创建第二份报告或返回未处理的完整性错误

#### Scenario: 原帖在锁定后改变
- **WHEN** 来源锁定后任一原帖被删除、编辑或变为非正常状态
- **THEN** 历史 Report 与其 Run SHALL 继续以锁定来源为依据，并在来源页保留可核验的历史输入
- **THEN** 系统不得使用原帖当前值改写任何已锁定来源、结果或 Word

### Requirement: 来源快照、Run 版本与指标时点
来源清单 SHALL 保存每个锁定成员的 `topic_id`、稳定排序键、发布时间、标题、已分离正文、末尾话题、投票文本快照、内容指纹，以及计算类别、情绪、反馈价值和风险所需的 AI 快照与版本/时间；还 SHALL 保存锁定当时的官方身份值及其判定来源。来源清单 MAY 保留到当前原帖的本地关联用于导航，但报告计算 MUST NOT 依赖该关联存在。系统不得在来源清单保存作者 OpenID、昵称、头像、评论、认证材料或上游响应。

系统 SHALL 同时锁定紧邻上一等长周期、同游戏、正常帖的正文、话题、投票、官方身份及用于热词、主题、情绪比较的 AI 快照；基线在重跑时不得重新选择。来源文本和基线文本 SHALL 仅对具备该游戏权限的认证运营人员在受保护追溯页可见，且不得进入默认报告详情、列表或 Word。

每个 Run SHALL 在统一 `metrics_as_of` 时点读取锁定成员的最新 `InteractionSnapshot`，并在同一运行时点读取该游戏、报告日期范围、`scope=ALL` 下已启用日粒度指标来源的 `GameCircleMetricSnapshot`。日指标只可使用 `period_start=period_end`、业务日完整落在报告范围内且 `publication_state=VERIFIED` 的快照；周指标、跨边界周期和待稳定性复核快照 SHALL 作为覆盖限制而非日指标值。互动和日指标可以随 Run 变化，但完成 Run 实际使用的互动值、日指标值、各自覆盖/缺失、快照时间与 `metrics_as_of` MUST 随该 Run 固定。计算、详情和 Word 不得以当前互动、当前日指标、当前原帖、当前官方作者配置或当前 AI 覆盖历史 Run。

系统 SHALL 保存递增 `run_number`、状态、开始/结束时间、数据质量、不可变 `result_payload` 与脱敏错误。确定性阶段 SHALL 使用不可对外渲染的内部检查点保存固定指标与证据；只有将该检查点与有效结论或“结论暂不可用”状态合成为完整结果的成功 Run 才可保存对外 `result_payload`。模型结论失败 SHALL 以受限结论状态完成 Run，不得清空或使确定性 Run 失败。默认详情 SHALL 展示最新成功 Run，并允许查看可访问的历史成功版本。

#### Scenario: 重跑使用同一成员但更新运行时证据
- **WHEN** 运营人员重跑一个已锁定 Report，且其中 400 帖的浏览/点赞/回复/分享已有变化
- **THEN** 新 Run SHALL 仍只分析相同 400 帖的锁定文本、话题、官方身份和 AI 快照
- **THEN** 新 Run SHALL 固定自身的互动和日指标证据，旧 Run 的结果不得被覆盖

#### Scenario: 官方作者配置在来源锁定后变更
- **WHEN** 报告来源锁定后任一官方作者配置被加入、移除或游戏名称改变
- **THEN** 已锁定来源与其历史 Run SHALL 保留锁定时的官方身份及来源
- **THEN** 系统不得以当前配置改写历史报告

#### Scenario: 互动快照覆盖不完整
- **WHEN** 已锁定成员中部分帖子在 `metrics_as_of` 前没有互动快照
- **THEN** Run SHALL 展示互动快照覆盖缺口和可用快照时间
- **THEN** 系统不得将缺失互动记为零值或将报告标记为失败

#### Scenario: 日指标尚待稳定性复核
- **WHEN** 报告范围内某日指标快照的 `publication_state` 为待稳定性复核，或其业务周期不完全属于报告范围
- **THEN** Run SHALL 将该来源/日期计入日指标覆盖限制而非采用其数值
- **THEN** 系统不得以周指标、跨边界指标或待复核指标填补该日值

#### Scenario: Worker 在首次锁定前中断
- **WHEN** Worker 在来源清单及其锁定标记提交前退出或租约失效
- **THEN** 该事务 SHALL 完全回滚，后续受限重试可以重新执行首次锁定
- **THEN** 系统不得保留部分来源行或将不完整范围用于计算

#### Scenario: Worker 在锁定后失败
- **WHEN** Worker 在来源锁定后遇到可恢复本地错误、进程中断或依赖暂时不可用
- **THEN** Job MAY 依既有受限重试策略重试，并必须复用已锁定来源与基线
- **THEN** 成功运行只能创建新的完整结果，失败记录不得包含半成品结论

### Requirement: 可解释的舆情分析与数据质量
报告 SHALL 将内容类别、情绪、反馈价值、风险、话题、互动、日指标和官方身份代表帖作为独立维度呈现。内容类别、情绪、反馈价值和风险分布 SHALL 仅使用锁定来源中的 AI 快照；未评估、空情绪、无法映射情绪、空反馈价值和不属于 `NONE`/`LOW`/`MEDIUM`/`HIGH` 的反馈价值 MUST 分别计入覆盖缺口，不得将非法反馈值展示为业务分类。

报告 SHALL 使用版本化本地游戏词典、主题词典和停用词，对锁定的标题、正文与投票文本进行 `jieba` 分词和热词计算；独立末尾话题 SHALL 单独聚合，不得混入热词、正文或投票分析。主题 SHALL 覆盖玩法策略、角色强度、抽卡付费、BUG 性能、活动福利、社交公会、难度平衡和情感评价；同一帖子可以匹配多个主题，页面和 Word MUST 标注主题计数可重叠。热词 SHALL 优先展示相对锁定上一等长周期基线的差异；无基线时 SHALL 仅展示当前高频词并披露限制。

报告 SHALL 按上海时区的来源发布时间保存正常帖量、可映射情绪量和主题量趋势，并按官方身份分组代表帖。互动总量和互动率 SHALL 保持既有最低浏览量保护；帖子标题是否为空 MUST NOT 参与官方身份判定。玩家代表帖可以形成玩家高互动观察；官方代表帖只能作为官方内容互动单列说明，并明确不构成玩家关注或反馈信号。日指标 SHALL 按指标来源、业务周期和原始口径展示；系统不得跨来源相加、构造综合分或将与帖子趋势的同期变化表述为因果。

数据质量摘要 SHALL 至少包括来源成员总数、文本缺口、AI 评估覆盖、情绪覆盖、反馈价值有效/缺失/无效覆盖、互动快照覆盖、日指标来源覆盖、互动和日指标快照时间、相对上期基线可用性、`source_locked_at`、`metrics_as_of` 及限制说明。缺少 AI、情绪、反馈、互动快照、日指标或基线 SHALL 是成功报告的显式限制，不得补零、推断正负面或表示无风险。

#### Scenario: AI 覆盖不完整
- **WHEN** 锁定来源中存在没有 AI 评估或没有可映射情绪的帖子
- **THEN** 报告 SHALL 分别展示类别与情绪覆盖率及未覆盖数量
- **THEN** 系统不得对这些帖子额外发送模型请求、重跑 AI 审核或以词典赋予情绪

#### Scenario: 一个帖子命中多个议题
- **WHEN** 一篇锁定正常帖同时命中抽卡付费和难度平衡主题词典
- **THEN** 报告 SHALL 在两个主题中分别计数
- **THEN** 页面和 Word SHALL 明确主题计数不可与帖子总数直接比较

#### Scenario: 无相对上期基线
- **WHEN** 锁定的上一等长周期没有可用同游戏正常帖
- **THEN** 报告 SHALL 标记热词基线不可用并只展示当前高频词
- **THEN** 系统不得伪造趋势、变化率或对比结论

#### Scenario: 历史 AI 反馈值不符合枚举
- **WHEN** 锁定来源的历史 AI 快照含非空但不属于反馈价值枚举的值
- **THEN** 报告 SHALL 将其计为反馈价值无效覆盖缺口
- **THEN** 默认报告、Word、日志和模型证据包不得输出该异常原文

#### Scenario: 历史反馈值已保存为规范中文标签
- **WHEN** 一个历史 Run 的反馈价值汇总保存为“低”“中”“高”或“无明确反馈价值”等规范中文标签
- **THEN** 报告详情 SHALL 将其与 `LOW`、`MEDIUM`、`HIGH`、`NONE` 枚举键一致地显示
- **THEN** 系统不得将该受控历史值渲染为空白标签或重新解释为无效覆盖

#### Scenario: 一个帖子命中多个议题和尾部话题
- **WHEN** 一篇锁定正常帖同时命中多个主题，且保存有末尾话题
- **THEN** 系统 SHALL 分别统计各主题和独立话题
- **THEN** 页面和 Word SHALL 明确主题可重叠，话题不属于热词词频

#### Scenario: 不同来源日指标同日可用
- **WHEN** 同一报告日期内多个日指标来源均有有效快照
- **THEN** 报告 SHALL 按来源分别展示其原始序列和快照时点
- **THEN** 系统不得把它们相加、平均或据此自动生成因果判断

#### Scenario: 日指标详情展示
- **WHEN** 成功 Run 含有已固定的日指标快照
- **THEN** 默认详情 SHALL 按业务日期和中文来源展示每个原始指标字段的中文名称、值和本地可读采集时间
- **THEN** 默认详情不得直接渲染原始指标 JSON、内部字段字典或 UTC ISO 时间字符串

### Requirement: 默认指标关联摘要与可追溯明细

成功 Run 的默认报告详情 SHALL 将日指标作为“运营指标关联”摘要呈现：每个 `MetricSource` 独立展示覆盖天数，以及同一原始指标的区间首末值与变化。默认摘要 MUST NOT 跨来源合计、平均、排名或生成综合评分，且不得将与帖子趋势的同期开合表述为因果。

完整的已固定日指标快照 SHALL 仍以可展开证据区提供，按业务日期、中文来源、原始指标字段和值及本地可读采集时间展示。该证据区的存在不得触发当前数据库、上游或模型重新读取。

#### Scenario: 多来源指标作为运营背景
- **WHEN** 一个成功 Run 同时含有多个日指标来源
- **THEN** 默认详情 SHALL 分来源展示各自的同口径摘要，不得合并为单一总指标
- **THEN** 人工运营人员可以展开固定证据区核验任一来源的逐日值和采集时间

### Requirement: 受约束的模型运营结论

系统 SHALL 在确定性报告结果成功后，从该 Run 已固定的白名单证据构造版本化模型输入。输入只可包含报告范围、数据质量、聚合分布、趋势、热词、独立话题、日指标证据、**玩家内容**代表帖的 ID/安全标题/汇总互动和稳定证据编号；不得包含作者身份、头像、完整正文、评论、认证信息、上游响应或当前数据库查询结果。官方内容代表帖不得进入模型输入，以免将官方内容互动误解释为玩家舆情。

模型输出 MUST 通过固定 JSON Schema 与服务端语义校验：结论项数量受限，每项 SHALL 以完整、带限定语的一至两句话表达并引用至少一个存在的证据编号，且不得包含自动处置、归责、确定因果、未被证据支持的数值或身份信息。Run SHALL 保存模型/提示词/证据 Schema 版本、输入哈希、结论状态、验证后的结论和脱敏错误分类。

模型调用、响应解析或语义校验失败时，确定性结果完整的 Run SHALL 仍标记成功并显示“模型结论暂不可用”；系统不得为此重跑帖子审核、自动重试模型调用、重新选源或阻止 Word 导出。系统 SHALL 在调用前持久化模型尝试标记和输入哈希；该标记存在但未保存有效结论时，恢复执行 MUST 直接将结论收敛为暂不可用，不得重新读取运行时指标或再次调用模型。

模型传输失败 SHALL 按固定、脱敏且可操作的分类保存和展示：连接超时、响应超时、请求发送超时、连接失败、鉴权失败、接口地址无效、限流、请求拒绝、服务端错误或无法进一步识别的传输失败。系统不得保存或展示上游响应正文、请求头、认证材料或原始异常消息。

#### Scenario: 模型结论引用确定性证据
- **WHEN** 模型为一个确定性分析成功的 Run 返回结构有效结论
- **THEN** 系统 SHALL 验证每个证据引用存在于该 Run 的证据包后才保存和展示
- **THEN** 页面和 Word SHALL 同时展示结论、引用证据和“仅供运营参考”限制

#### Scenario: 中文可核验的结论证据展示
- **WHEN** 成功 Run 含有已验证的模型结论
- **THEN** 报告详情和 Word SHALL 将结论类型与引用证据 ID 映射为中文，并展示仅由该 Run 固定 payload 派生的简短佐证摘要
- **THEN** 页面 SHALL 以结论正文和引用式证据分层展示，不得展示英文内部 ID、作者信息、正文、当前数据库数据或上游响应

#### Scenario: 官方最高互动帖
- **WHEN** 官方内容帖在互动总量或互动率排名中居首
- **THEN** 报告 SHALL 将其表述为官方内容互动，并明确不作为玩家关注或反馈信号
- **THEN** 该官方代表帖不得进入模型结论证据包；历史 Run 的展示投影可修正文案，但不得改写其持久化结果

#### Scenario: 模型输出不可用
- **WHEN** 模型请求失败、返回非 JSON、Schema 不匹配或引用不存在
- **THEN** 系统 SHALL 保存固定脱敏结论失败状态并保留确定性报告结果
- **THEN** 报告详情与 Word SHALL 可用且明确模型结论暂不可用

#### Scenario: 模型响应超时
- **WHEN** 模型服务在配置的读取超时内未返回
- **THEN** Run SHALL 保存 `MODEL_READ_TIMEOUT` 并在报告详情、报告配置的最近失败提示和 Word 中显示“模型响应超时”
- **THEN** 系统不得暴露原始异常、重试本次调用或使确定性报告失败

#### Scenario: 模型调用期间 Worker 中断
- **WHEN** Run 已固定确定性结果并登记模型调用尝试，但 Worker 在保存模型结论前中断
- **THEN** 后续恢复 SHALL 复用已固定的确定性结果并将结论标为暂不可用
- **THEN** 系统不得重新读取互动/日指标或第二次调用模型

### Requirement: 按报告算法版本执行与重跑

系统 SHALL 以 `PublicOpinionReport.analysis_version` 选择版本注册表中的来源输入适配器、确定性计算器、结果 Schema、Word 渲染器及模型结论阶段。已存在 Report 的人工重跑 MUST 使用其保存的算法版本；新算法不得隐式覆盖旧 Report 的重跑口径。

已发布但不包含模型结论的旧算法版本 SHALL 继续使用其原有本地计算和导出路径，不得因重跑调用模型或读取新版本专属字段。系统遇到未知或已移除的算法版本时 SHALL 安全失败、保留已有成功 Run，并返回固定可处理错误。

#### Scenario: 旧版本报告重跑
- **WHEN** 运营人员重跑一个保存了旧算法版本的未到期 Report
- **THEN** 系统 SHALL 以该旧版本计算器和 Word 渲染器生成新的 Run
- **THEN** 系统不得改用新版本字段、日指标语义或模型结论调用

#### Scenario: 未知算法版本报告重跑
- **WHEN** Report 保存的算法版本未在当前版本注册表中提供
- **THEN** 系统 SHALL 拒绝该次重跑并保留所有已有成功 Run
- **THEN** 系统不得用默认最新算法替代执行或覆盖历史结果

### Requirement: 报告模型结论的独立配置与可解释状态

系统 SHALL 在系统配置的“舆情报告 Worker”卡片提供与“配置 AI 审核”同级的受认证“配置舆情报告”弹窗。该弹窗 SHALL 只管理 `PUBLIC_OPINION_CONCLUSION_ENABLED`，并只读展示既有 AI 连接的服务地址、模型名称及密钥是否已配置；不得回显、保存或修改密钥、AI 服务地址、模型名称、超时或 AI 审核策略。系统不得为该配置增加独立跳转页面。

页面 SHALL 基于当前配置和最近一个本游戏范围内包含结论快照的 Run，展示下列互斥的当前状态：开关关闭时为“未启用”；开关开启但 AI 服务地址、模型名称或密钥缺失时为“模型连接未配置”；两者完整时为“已就绪，可在新的报告运行中生成结论”。若最近结论 Run 有固定脱敏失败分类，页面 MAY 在当前状态下额外说明最近失败分类，但不得以历史 Run 的状态替代当前配置状态。

保存开关 SHALL 仅修改受控运行配置，并只要求重启舆情报告 Worker 加载。页面 MUST 明确：已完成 Run 不会自动生成或补写结论；运营人员必须创建报告或重跑固定来源以创建新的 Run。该页不得提供补写既有 Run、重发模型调用或修改不可变报告结果的操作。

#### Scenario: 模型结论默认关闭
- **WHEN** 运营人员打开报告配置页且 `PUBLIC_OPINION_CONCLUSION_ENABLED` 未配置或为 false
- **THEN** 页面 SHALL 显示“未启用”及启用说明
- **THEN** 页面不得将该状态显示为模型传输或 Schema 故障

#### Scenario: 启用后模型连接不完整
- **WHEN** 运营人员启用模型结论，但 AI 服务地址、模型名称或密钥尚未完整配置
- **THEN** 页面 SHALL 显示“模型连接未配置”，并指向既有 AI 连接配置位置
- **THEN** 系统不得在保存开关时调用模型、创建报告或改变既有 Run

#### Scenario: 保存报告结论开关
- **WHEN** 运营人员在报告配置页保存模型结论开关
- **THEN** 系统 SHALL 仅写入 `PUBLIC_OPINION_CONCLUSION_ENABLED` 并提示重启舆情报告 Worker
- **THEN** 现有报告与其结论快照 SHALL 保持不变

### Requirement: 报告工作区、来源追溯与 Word 导出
舆情报告工作区 SHALL 提供稳定报告列表、创建入口、Run 状态、成功版本详情、历史版本切换、来源追溯与重跑入口。运行中页面 SHALL 只展示状态和进度摘要，不得展示半成品结论或 Word 导出入口。报告详情与 Word MUST 标注“仅供运营参考”，不得形成自动审核、处置或问题处理结论。

来源追溯页 SHALL 对已认证且具有报告所属游戏范围权限的运营人员分页展示锁定 `topic_id`、发布时间、内容指纹、文本与锁定 AI 摘要，并明确其为历史输入。当前原帖不存在或状态变化时，该页仍 SHALL 可用于核验。来源页面以外不得展示作者身份或完整正文。

系统 SHALL 仅允许已认证运营人员为指定的已完成 Run 请求 Word 导出。导出 SHALL 使用 `python-docx` 从该 Run 的 `result_payload` 流式生成 `.docx` 响应，包含范围、Run 版本、`source_locked_at`、`metrics_as_of`、算法/模板版本、数据质量和限制、聚合结果、代表帖表格及运营参考标记。导出不得创建或更新 Report/Run、重新读取帖子数据、创建后台任务、保存 Word 文件或访问外部服务。

#### Scenario: 查看已完成报告
- **WHEN** 运营人员打开一个已完成 Run 的详情
- **THEN** 页面 SHALL 从该 Run 的快照展示各分析区块、限制说明和代表帖本地链接
- **THEN** 页面不得创建 Job、重新计算报告、调用 CDP 或请求上游

#### Scenario: 导出历史成功版本
- **WHEN** 运营人员选择一个非最新的已完成 Run 并请求导出
- **THEN** 系统 SHALL 返回仅由该 Run 快照渲染的 Word 文档
- **THEN** 系统不得改用最新 Run、重算报告或查询原帖正文

#### Scenario: 导出未完成或越权报告
- **WHEN** 运营人员请求导出待执行、运行中、失败或不属于当前游戏范围的 Run
- **THEN** 系统 SHALL 拒绝导出并返回固定可处理原因
- **THEN** 系统不得生成空文档、重新计算报告或泄露报告内容

### Requirement: 来源保留与受控删除
系统 SHALL 为每个 Report 保存明确的来源保留截止时间，并在来源可用期间拒绝对单一来源行的任意删除或修改。到期清理 SHALL 按完整 Report 删除来源、本期/基线文本、所有 Run 结果和主记录；清理后不得重跑、查看或导出该报告。清理日志只可记录报告标识、数量、时间和原因，不得记录文本。

若必须在保留期前删除，受权限的管理操作 MUST 删除完整 Report，而不得篡改单条来源以保持旧结果看似可用。删除执行前，系统 SHALL 阻止新的 Run 与 Word 导出。

#### Scenario: 报告到期清理
- **WHEN** 受控清理任务发现来源保留期已到的 Report
- **THEN** 系统 SHALL 以该 Report 为单位删除其来源、基线、Run 和主记录
- **THEN** 系统不得留下可访问的结果、来源文本或 Word 文件
