## Context

视频 Worker 先在本地受控目录下载媒体，再以 `ffprobe` 取得时长；提取记录保存创建时的 `VIDEO_MAX_DURATION_SECONDS` 快照。当前实现把任何超过该快照的媒体标记为 `SKIPPED_LIMIT` 并停止，因此开头、中段和片尾的违规信息均无法进入审核。运行时当前可将该值设为 60 秒，媒体读取仍已有字节、网络、处理时间和 OCR 预算边界。

## Goals / Non-Goals

**Goals:**

- 以一个可测试的窗口规划器为所有视频生成首、中、尾采样区间；总覆盖时长不超过提取记录的时长预算快照。
- 对预算内视频自然合并为完整区间，对超预算视频保留分布式视觉证据机会。
- 使提取记录、审核界面和 AI 输入明确表达实际采样区间与 ASR 未执行的原因，不能把局部覆盖伪装成完整审核。
- 保持任意时长视频的候选帧上界与当前完整预算采样一致，继续先做本地二维码存在检测，再受 dHash 与 OCR 预算约束。
- 以向上取整的毫秒时长判断边界，避免分数秒超过上限时因截断被当作未超限。

**Non-Goals:**

- 不取消 `VIDEO_MAX_DURATION_SECONDS`，不对超过预算的视频进行整段音频提取或 ASR。
- 不改变无凭据媒体读取、URL/网络地址校验、字节上限、处理超时或外部 OCR/ASR 数据边界。
- 不重跑历史 `SKIPPED_LIMIT` 记录；运营人员可沿用既有“重新评估”显式创建新尝试。

## Decisions

### 1. 时长配置定义为统一的采样时长预算

将 `VIDEO_MAX_DURATION_SECONDS` 在界面与文档中命名为“最大采样时长（秒）”。对于视频时长 `D` 和预算快照 `B`，窗口规划器先计算 `S = min(D, B)`，再返回三个半开区间。三个窗口的长度总和恰为 `S`：前两个长度为 `floor(S / 3)`，末个长度为 `S - 2 * floor(S / 3)`；其起点分别为 `0`、`floor((D - 中间窗口长度) / 2)` 和 `D - 末窗口长度`。规划器按时间排序并合并重叠或相邻窗口。

因此 `D <= B` 时三个相邻窗口合并为 `[0, D)`，完整覆盖视频；`D=90`、`B=60` 秒时得到 `[0,20)`、`[35,55)`、`[70,90)`。这是同一数学规划器的不同结果，不存在两套提取管线。备选方案“提高或移除上限”会令抽帧与 ASR 成本随时长线性增长；“仅首尾采样”会遗漏片中引流；两者均不采用。

### 2. 全局帧密度只由实际视频首尾决定

关键帧生成器接收规划后的窗口，而非时长分支。它在每个窗口内按每秒一帧生成基础候选；仅当该窗口与实际视频 `[0,3)` 或 `[D-3,D)` 相交时，用每 250ms 的候选替换该范围内的基础候选。候选时间去重并排序后进入现有二维码、dHash 与 OCR 流程。

这使完整覆盖的视频保持当前节奏：30 秒为 48 帧、60 秒为 78 帧；90 秒且预算 60 秒同样为 78 帧，而不是为三个窗口分别加密后增加到 114 帧。备选方案“每个窗口首尾都高密度抽帧”会使超长媒体绕过已有候选帧成本预期，拒绝采用。

### 3. 采样区间是唯一的追溯事实

`VideoExtraction` 新增 `sampled_intervals_ms` JSON 字段，保存排序、互不重叠的毫秒半开区间，例如 `[[0,20000],[35000,55000],[70000,90000]]`。空数组表示尚未成功规划采样，不能据此推断历史记录已完整覆盖；迁移不改写既有记录。单一 `[0,D)` 表示完整采样，多个区间表示分布式采样。

超预算视频完成分布式视觉采样后以 `PARTIAL + video_duration_distributed_sampling` 结束。区间字段而非 `error_summary` 是覆盖范围的唯一依据；错误码仅用于终态分类。审核界面和 AI 输入都从该字段生成运营可读的范围说明。备选方案是存储“完整/首尾”枚举，但它无法表达实际中段窗口与未来不同预算，拒绝采用。

### 4. 仅完整覆盖的视频进入 ASR

当规划结果为单一完整区间、存在可处理音轨且 ASR 配置完整时，沿用现有整段音频转写。多个分布式区间时跳过整段音频和 ASR，并由范围说明明确这一事实。这样时长预算仍约束最昂贵、最难分段的外部输入；视觉证据仍可参与 AI 审核。截取多个音频片段后转写需要额外定义时间偏移、提供方能力和成本边界，本次不引入。

### 5. 使用保守毫秒归一化

`ffprobe` 的秒数字符串以 `Decimal` 解析并向上取整到毫秒，时长比较只使用该值。恰好为 60 秒仍完整采样；任何非零分数超过 60 秒都会正确进入分布式采样。拒绝浮点截断，因为它可能使超预算媒体绕过采样预算。

## Risks / Trade-offs

- [分布式窗口未覆盖的时间含违规] → 界面与模型输入列出实际区间、明确未覆盖其他时间且未执行 ASR；人工可据此复核。
- [长视频下载仍可能昂贵] → 保持已有 `VIDEO_MAX_BYTES`、连接/读取超时及受控 HTTPS 读取；字节超限仍为 `SKIPPED_LIMIT`。
- [部分证据被误视为整段结论] → 固定分类与区间字段区分“受控分布式采样”与完整覆盖，且状态为 `PARTIAL`。
- [历史记录语义不一致] → 不迁移重写旧记录；新字段默认“未采样”，历史仍按原有 `SKIPPED_LIMIT` 说明展示。

## Migration Plan

1. 添加可空/默认“未采样”的范围字段及迁移，不改写既有提取结果。
2. 部署 Worker 与 Web 后，新的任务按统一窗口规划执行；已有超限记录只在人工重新评估时创建新尝试。
3. 以 30 秒、60 秒、60.001 秒和 90 秒视频的单元测试验证完整合并、分布式窗口、全局帧预算、ASR 跳过和资源限制；复核页面与模型输入不含 URL、令牌、Cookie 或工具输出。
4. 回滚时停止视频 Worker，并回退应用代码；新字段可保留，已产生的 `PARTIAL` 记录仍可被旧版本按现有终态语义读取。

## Open Questions

无。三个窗口与真实视频首尾高密度策略均是固定、可复核的当前产品规则；后续如需配置化将另行评估成本和证据质量。
