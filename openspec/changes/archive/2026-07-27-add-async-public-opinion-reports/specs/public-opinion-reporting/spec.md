## ADDED Requirements

### Requirement: 锁定范围的异步舆情报告
系统 SHALL 允许已认证运营人员为一个可管理游戏和上海时区日期范围创建 `PUBLIC_OPINION_REPORT`。创建时 SHALL 固定 `source_appid`、起止日期、`status=2` 正常帖规则、报告算法版本和模板版本；默认范围为最近 30 天，范围 MUST 为 1 至 90 天。任务只可分析范围内的 `OriginalPost`，不得读取候选转发帖、待判定帖、非正常状态原创帖、评论正文或上游数据。

首次实际执行时，系统 SHALL 锁定精确的来源成员；锁定后该报告的自动重试和人工重跑 MUST 使用相同成员，即使原帖随后被删除、编辑、变为非正常状态，或范围内新增帖子。系统 SHALL 使用稳定 Report、来源清单和 Run 版本表示该关系，不得用可覆盖的单一结果记录代替。

同一游戏、范围和算法版本在存在待执行或执行中的 Run 时 SHALL 返回既有 Report 与 Run；系统 MUST 使用既有 `BackgroundJob.active_coalescing_key` 的数据库唯一约束在并发提交下保证该约束。每个 Run SHALL 一对一关联其 Job。已完成或失败的 Run 不得被覆盖；运营人员重新生成 SHALL 在同一已锁定 Report 下创建新的 Run 与 Job，不得重新选源。

#### Scenario: 首次执行锁定 400 帖
- **WHEN** 报告的首次 Worker 执行按范围选中 400 篇正常原创帖
- **THEN** 系统 SHALL 将这 400 个成员、稳定排序键及分析所需内容/AI 快照原子锁定为来源清单
- **THEN** 后续重试或重跑不得因状态、内容、AI 或日期范围数据变化加入、移除或替换任何成员

#### Scenario: 创建默认范围报告
- **WHEN** 运营人员在当前可管理游戏中未修改日期范围而创建报告
- **THEN** 系统 SHALL 创建或复用最近 30 天正常原创帖的本地后台任务
- **THEN** HTTP 请求不得建立 CDP 会话、请求上游、执行审核或写操作

#### Scenario: 拒绝无效范围
- **WHEN** 运营人员提交超过 90 天、开始日晚于结束日、没有可管理游戏或创建前帖子数超过受限上限的范围
- **THEN** 系统 SHALL 拒绝创建任务并返回固定可处理原因
- **THEN** 系统不得创建部分报告、后台任务或 Word 文件

#### Scenario: 并发提交相同范围
- **WHEN** 两个创建请求同时提交相同游戏、日期范围和算法版本
- **THEN** 系统 SHALL 只持久化一份活跃 Run、一个关联 Job 和一个稳定 Report
- **THEN** 两个请求均不得因并发冲突创建第二份报告或返回未处理的完整性错误

#### Scenario: 原帖在锁定后改变
- **WHEN** 来源锁定后任一原帖被删除、编辑或变为非正常状态
- **THEN** 历史 Report 与其 Run SHALL 继续以锁定来源为依据，并在来源页保留可核验的历史输入
- **THEN** 系统不得使用原帖当前值改写任何已锁定来源、结果或 Word

### Requirement: 来源快照、Run 版本与指标时点
来源清单 SHALL 保存每个锁定成员的 `topic_id`、稳定排序键、发布时间、标题/正文/投票文本快照、内容指纹，以及计算类别、情绪、反馈价值和风险所需的 AI 快照与版本/时间。来源清单 MAY 保留到当前原帖的本地关联用于导航，但报告计算 MUST NOT 依赖该关联存在。系统不得在来源清单保存作者身份、评论、认证材料或上游响应。

系统 SHALL 同时锁定紧邻上一等长周期、同游戏、正常帖的文本与用于热词、主题、情绪比较的 AI 基线快照；基线在重跑时不得重新选择。来源文本和基线文本 SHALL 仅对具备该游戏权限的认证运营人员在受保护追溯页可见，且不得进入默认报告详情、列表或 Word。

每个 Run SHALL 在统一 `metrics_as_of` 时点读取锁定成员的最新 `InteractionSnapshot`。互动数据可以随 Run 变化，但完成 Run 的互动值、覆盖率、快照最早/最晚时间与 `metrics_as_of` MUST 随该 Run 固定。计算、详情和 Word 不得以当前互动、当前原帖或当前 AI 覆盖历史 Run。

系统 SHALL 保存递增 `run_number`、状态、开始/结束时间、数据质量、不可变 `result_payload` 与脱敏错误。只有完整的成功 Run 可保存结果；失败 Run MUST NOT 持久化半成品。默认详情 SHALL 展示最新成功 Run，并允许查看可访问的历史成功版本。

#### Scenario: 重跑使用同一成员但更新互动
- **WHEN** 运营人员重跑一个已锁定 Report，且其中 400 帖的浏览/点赞/回复/分享已有变化
- **THEN** 新 Run SHALL 仍只分析相同 400 帖的锁定文本与 AI 快照
- **THEN** 新 Run SHALL 记录自身 `metrics_as_of` 和互动结果，旧 Run 的互动结果不得被覆盖

#### Scenario: 互动快照覆盖不完整
- **WHEN** 已锁定成员中部分帖子在 `metrics_as_of` 前没有互动快照
- **THEN** Run SHALL 展示互动快照覆盖缺口和可用快照时间
- **THEN** 系统不得将缺失互动记为零值或将报告标记为失败

#### Scenario: Worker 在首次锁定前中断
- **WHEN** Worker 在来源清单及其锁定标记提交前退出或租约失效
- **THEN** 该事务 SHALL 完全回滚，后续受限重试可以重新执行首次锁定
- **THEN** 系统不得保留部分来源行或将不完整范围用于计算

#### Scenario: Worker 在锁定后失败
- **WHEN** Worker 在来源锁定后遇到可恢复本地错误、进程中断或依赖暂时不可用
- **THEN** Job MAY 依既有受限重试策略重试，并必须复用已锁定来源与基线
- **THEN** 成功运行只能创建新的完整结果，失败记录不得包含半成品结论

### Requirement: 可解释的舆情分析与数据质量
报告 SHALL 将内容类别、情绪、议题和互动作为独立维度呈现。内容类别、情绪、反馈价值和风险分布 SHALL 仅使用锁定来源中的 AI 快照；未评估、空情绪或无法映射为正面/中性/负面的情绪值 MUST 计入覆盖缺口，不得以手工情感词典替代。

报告 SHALL 使用版本化本地游戏词典、主题词典和停用词，对锁定的标题、正文与投票文本进行 `jieba` 分词和热词计算。主题 SHALL 覆盖玩法策略、角色强度、抽卡付费、BUG 性能、活动福利、社交公会、难度平衡和情感评价；同一帖子可以匹配多个主题，页面和 Word MUST 标注主题计数可重叠。热词 SHALL 优先展示相对锁定上一等长周期基线的差异；无基线时 SHALL 仅展示当前高频词并披露限制。

报告 SHALL 按上海时区的来源发布时间保存正常帖量、可映射情绪量和主题量趋势。情绪占比 MUST 只以可映射情绪帖子为分母，并与情绪覆盖率一同展示。运营观察 SHALL 由算法版本内固定规则生成，至多五条；每条 MUST 引用报告内的明确指标并标注“需人工核验”，不得推断原因、归责或形成自动处置建议。

数据质量摘要 SHALL 至少包括来源成员总数、文本缺口、AI 评估覆盖、情绪覆盖、互动快照覆盖、互动快照最早/最晚时间、相对上期基线可用性、`source_locked_at`、`metrics_as_of` 及限制说明。缺少 AI、情绪、互动快照或基线 SHALL 是成功报告的显式限制，不得补零、推断正负面或表示无风险。

#### Scenario: AI 覆盖不完整
- **WHEN** 锁定来源中存在没有 AI 评估或没有可映射情绪的帖子
- **THEN** 报告 SHALL 分别展示类别与情绪覆盖率及未覆盖数量
- **THEN** 系统不得对这些帖子额外发送模型请求、重跑 AI 审核或以词典赋予情绪

#### Scenario: 一个帖子命中多个议题
- **WHEN** 一篇锁定正常帖同时命中抽卡付费和难度平衡主题词典
- **THEN** 报告 SHALL 在两个主题中分别计数
- **THEN** 页面和 Word SHALL 明确主题计数不可与帖子总数直接比较

#### Scenario: 无相对上期基线
- **WHEN** 锁定的上一等长周期没有可用同游戏正常帖
- **THEN** 报告 SHALL 标记热词基线不可用并只展示当前高频词
- **THEN** 系统不得伪造趋势、变化率或对比结论

### Requirement: 报告工作区、来源追溯与 Word 导出
舆情报告工作区 SHALL 提供稳定报告列表、创建入口、Run 状态、成功版本详情、历史版本切换、来源追溯与重跑入口。运行中页面 SHALL 只展示状态和进度摘要，不得展示半成品结论或 Word 导出入口。报告详情与 Word MUST 标注“仅供运营参考”，不得形成自动审核、处置或问题处理结论。

来源追溯页 SHALL 对已认证且具有报告所属游戏范围权限的运营人员分页展示锁定 `topic_id`、发布时间、内容指纹、文本与锁定 AI 摘要，并明确其为历史输入。当前原帖不存在或状态变化时，该页仍 SHALL 可用于核验。来源页面以外不得展示作者身份或完整正文。

系统 SHALL 仅允许已认证运营人员为指定的已完成 Run 请求 Word 导出。导出 SHALL 使用 `python-docx` 从该 Run 的 `result_payload` 流式生成 `.docx` 响应，包含范围、Run 版本、`source_locked_at`、`metrics_as_of`、算法/模板版本、数据质量和限制、聚合结果、代表帖表格及运营参考标记。导出不得创建或更新 Report/Run、重新读取帖子数据、创建后台任务、保存 Word 文件或访问外部服务。

#### Scenario: 查看已完成报告
- **WHEN** 运营人员打开一个已完成 Run 的详情
- **THEN** 页面 SHALL 从该 Run 的快照展示各分析区块、限制说明和代表帖本地链接
- **THEN** 页面不得创建 Job、重新计算报告、调用 CDP 或请求上游

#### Scenario: 导出历史成功版本
- **WHEN** 运营人员选择一个非最新的已完成 Run 并请求导出
- **THEN** 系统 SHALL 返回仅由该 Run 快照渲染的 Word 文档
- **THEN** 系统不得改用最新 Run、重算报告或查询原帖正文

#### Scenario: 导出未完成或越权报告
- **WHEN** 运营人员请求导出待执行、运行中、失败或不属于当前游戏范围的 Run
- **THEN** 系统 SHALL 拒绝导出并返回固定可处理原因
- **THEN** 系统不得生成空文档、重新计算报告或泄露报告内容

### Requirement: 来源保留与受控删除
系统 SHALL 为每个 Report 保存明确的来源保留截止时间，并在来源可用期间拒绝对单一来源行的任意删除或修改。到期清理 SHALL 按完整 Report 删除来源、本期/基线文本、所有 Run 结果和主记录；清理后不得重跑、查看或导出该报告。清理日志只可记录报告标识、数量、时间和原因，不得记录文本。

若必须在保留期前删除，受权限的管理操作 MUST 删除完整 Report，而不得篡改单条来源以保持旧结果看似可用。删除执行前，系统 SHALL 阻止新的 Run 与 Word 导出。

#### Scenario: 报告到期清理
- **WHEN** 受控清理任务发现来源保留期已到的 Report
- **THEN** 系统 SHALL 以该 Report 为单位删除其来源、基线、Run 和主记录
- **THEN** 系统不得留下可访问的结果、来源文本或 Word 文件
