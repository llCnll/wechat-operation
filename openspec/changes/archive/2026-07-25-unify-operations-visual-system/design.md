## Context

`posts/operations_base.html` 已为内容管理、禁言管理、AI 操作复审和运营分析提供共用 topbar，但主题切换的标记、初始化脚本和深色 token 均留在 `templates/admin/base_site.html` 与 `admin_console.css`。结果是同一导航栏在不同页面具有不同能力；若逐页复制主题代码，页面偏好与可访问名称会漂移。三个目标页还承载不同风险级别的任务：内容管理有人工上游处置、AI 复审有纠正处置、运营分析以只读指标为主。

## Goals / Non-Goals

**Goals:**

- 建立认证运营页共用的主题根属性、太阳/月亮切换控件、偏好持久化与基础视觉 token。
- 在不改变业务交互的前提下，使内容管理、AI 操作复审和运营分析与系统配置拥有一致的导航、表面、表单、状态和对话框语言。
- 让每类工作台保留适合其任务的内容结构：队列详情、复审卡片、指标图表。
- 为深浅模式、无 JavaScript、窄屏和高风险表单保留可读、可操作的降级路径。

**Non-Goals:**

- 不把运行控制台的流程、服务卡或配置面板复制到业务页。
- 不改变 URL、筛选参数、History API、POST/CSRF、CDP 状态查询、审核/处置规则、图表数据或报表计算。
- 不引入前端构建、远程字体、远程脚本、数据库迁移或新的 API。

## Decisions

### 1. 以共享运营壳持有主题，而非由页面各自实现

创建一个本地主题组件：topbar 在全部认证运营页展示同一枚 Lucide 太阳/月亮切换按钮；共享脚本只设置根 `data-operations-theme` 与更新可访问名称，并以一个固定 localStorage key 保存偏好。`operations_base.html` 与 Django Admin 的 `base_site.html` 都引入该组件，页面模板不得重复主题脚本或开关。

现有 `operations-console-theme` 仅作为一次性兼容读取来源；共享键写入后成为唯一来源。替代方案是为每页加入独立开关和 key；实现快但必然产生不同页面主题不一致、重复维护和错误的按钮状态，因此不采用。

### 2. 分离跨页 token 与页面特有布局

新增本地共享样式层，负责 topbar、页面底色、文本、边框、焦点、通用按钮/输入、反馈与 dialog 的深浅 token。`operations.css`、`admin_console.css` 和 `metric_workspace.css` 只在各自负责的页面结构上使用该 token，不得为相同的导航栏、主题开关或基础色重复定义另一套逻辑。

主题使用根属性选择器而不是依赖单一 `configuration-dashboard` body class，以支持运行配置、内容管理、AI 复审和报表。替代方案是将所有页面 CSS 合并为一个文件；会扩大加载和回归范围，也会把高密度队列、图表与管理台布局耦合，故不采用。

### 3. 共享层级，不强制统一内容版式

所有目标页采用“页面标题/上下文 → 筛选或控制 → 主工作面”的可扫读层级，以及受控的卡片、边界和焦点状态。内容管理保持双栏队列与详情及禁言管理列表；AI 复审保持筛选、记录卡、证据折叠与明确的纠正对话框；运营分析保持周期工具栏、KPI、异常、趋势和图表。颜色仅强化状态，绝不成为高风险操作的唯一信号。

### 4. 主题切换只影响呈现

主题初始化不得发起网络请求、创建 Job、调用 CDP、变更表单值、筛选或滚动位置。脚本不可用时页面保持默认浅色、完整可读，固定 GET/POST 表单与既有客户端图表交互不受影响。所有现有图标替换或新增时使用仓库内 Lucide SVG，不使用 Emoji、Unicode 图形符号或字体图标作为界面图标。

### 5. 以三种工作模式重构工作面，而非只增加 token 覆盖

三个业务页 SHALL 共享系统配置的精密、克制且具层次感的视觉语言，但不得被统一成同一种卡片堆叠：

- **内容管理 / 禁言管理**是高密度决策台。标题区呈现当前工作范围与队列语境；筛选成为独立的控制带；队列与详情形成一张连续、带明确分割与焦点反馈的工作画布。禁言管理保持表格的横向扫描效率，并将批量和维护操作视觉降级为次要区。
- **AI 操作复审**是审计工作台。记录以具有清晰时间、动作、证据和确认区的纵向审计卡呈现；异常纠正必须以危险边界和显式最终操作突出，不能被装饰性动效掩盖。
- **运营分析**是数据叙事工作台。业务日和周期控制是页面的起始镜头，KPI 具有主次节奏，异常区明确引导进入趋势，图表与表格位于连续分析画布。数据本身优先于装饰。

页面仅使用仓库中的 Lucide SVG 作为操作、导航、状态和提示图标；不以 Emoji、Unicode 符号、文字伪图标或字体图标承载界面语义。允许为浏览器可访问性保留文字标签。

视觉目标参考高品质数字产品的沉浸感：克制的层级渐变、非侵入式网格/光晕、流畅且可关闭的微动效、强而可读的字体尺度与留白。它不意味着引入远程资源、Canvas、WebGL、构建链或会影响审核/处置确定性的实验性交互。

## Risks / Trade-offs

- [深色 token 覆盖不足，旧页面出现浅色孤岛] → 按页面表面、表单、表格/图表、状态与 dialog 建立深色验收清单和结构测试。
- [公共 CSS 意外改变 Django Admin] → 基础样式以 `data-operations-theme` 与明确页面根类限定；Admin 专属运行控制台规则继续留在其样式文件。
- [视觉改造误触发审核或报表行为] → 不修改视图、路由、表单 action、脚本业务逻辑或数据查询；最小验证覆盖同源 POST、CSRF、筛选和只读报表边界。
- [主题记忆影响用户排障] → 默认浅色，切换仅为当前浏览器偏好，按钮始终说明将切换到的模式。
- [视觉表现压过高风险操作] → 高风险按钮保留文字、危险色、确认 dialog 与键盘焦点；动效遵从 `prefers-reduced-motion`，并不参与任何状态判断。

## Migration Plan

1. 先落地共享主题资产与 topbar，并兼容读取旧系统配置偏好。
2. 分页接入内容管理、AI 复审和运营分析的结构样式与深色 token，不修改其服务端行为。
3. 采集静态资源并仅重启 Web；回滚只移除共享静态资产和模板引用，localStorage 中的无害偏好可保留。
