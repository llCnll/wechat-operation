## Why

当前 `/admin/` 仍是 Django 默认后台：视觉与运营工作台割裂，且候选帖、原创帖、AI 结果、审计和后台任务等运营数据默认存在编辑入口。这会使运营人员在两个审核入口之间切换，也增加误改采集事实与审计记录的风险。

现在需要将它收敛为与工作台一致的“系统配置与追溯台”：只保留必要的配置编辑和受控同步，将业务数据改为可搜索、可筛选、可追溯的只读视图。

## What Changes

- 重构 `/admin/` 首页、导航、列表和详情样式，使其延续内容管理台的品牌、色彩与信息层级，并提供返回内容管理、运营分析的明确入口。
- 将帖子、媒体、互动快照、OCR、AI 评估、风险证据、审核任务、回复草案、操作审计和后台任务收敛为只读追溯数据；保留搜索、筛选、详情查看和关联跳转。
- 移除 Django Admin 中重复的帖子审核与上游处置入口，人工处置只能从内容管理工作台发起。
- 保留可管理游戏目录与审核策略版本/规则的受控编辑；游戏目录同步仍是唯一需要受控 Chrome 登录态的 Admin 动作。
- 提供幂等的默认审核策略初始化命令；首页以可折叠摘要展示唯一启用策略的生效规则，规则列表同时保留风险编码和中文释义，避免运营人员只能看到版本名称。
- 调整 Admin 的新增、修改、删除和批量动作可见性，避免将技术数据模型误认为运营配置。

## Capabilities

### New Capabilities

- `administration-configuration-console`: 定义系统配置与只读追溯台的导航、视觉、模型访问边界和受控配置动作。

### Modified Capabilities

- 无。

## Impact

- 影响 `posts/admin.py`、`reviews/admin.py`、`jobs/admin.py` 及 Django Admin Site 配置。
- 新增 Admin 模板与静态样式，复用现有运营工作台的视觉语言但不耦合其业务页面。
- 影响 `/admin/` 中各模型的权限与可见操作；不修改数据库结构、CDP 读取契约、Worker 消费逻辑或工作台处置 API。
