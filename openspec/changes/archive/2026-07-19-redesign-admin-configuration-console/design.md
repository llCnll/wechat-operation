## Context

内容管理工作台已经承载帖子阅读、AI 建议和人工处置，但 `/admin/` 仍直接暴露 Django 默认后台。当前 `posts`、`reviews`、`jobs` 的多张技术数据模型可被编辑，`ReviewTaskAdmin` 还保留与工作台重复的上游处置入口。系统不区分角色权限，因此需要依靠清晰的信息架构和服务端访问策略降低误操作，而不是新增一套权限体系。

## Goals / Non-Goals

**Goals:**

- 将 `/admin/` 定位为“系统配置与追溯台”，在视觉、导航与术语上与内容管理工作台一致。
- 对采集事实、AI 输出、人工审核、审计与任务队列实施服务端只读限制，同时保留检索、筛选、关联查看与详情追溯。
- 将所有帖子审核和上游处置收敛到内容管理工作台，消除 Admin 中重复且风格不一致的操作入口。
- 仅保留审核策略版本/规则的配置编辑，以及通过受控 Chrome 同步游戏目录的动作。

**Non-Goals:**

- 不替换 Django Admin、引入前后端分离或新增角色权限。
- 不变更数据库结构、采集/AI Worker、CDP 读取契约或工作台处置 API。
- 不在本次实现策略编辑的发布审批、版本对比或回滚工作流。

## Decisions

### 1. 在默认 Django Admin 上建立配置台外壳

使用项目级 `admin/base_site.html`、`admin/index.html` 和专用静态样式覆盖默认品牌、导航和首页分组，而不创建第二个 AdminSite 或独立配置应用。顶部将提供“内容管理”“运营分析”“系统配置”导航，并复用工作台的浅纸色、青绿色、珊瑚色和圆角层级。

选择该方案是因为它保留 Django Admin 的认证、消息、列表、搜索、筛选和可访问性能力，改造范围集中且便于后续迭代。替代方案是单独实现配置页面；它会重复模型列表与表单维护成本，当前没有足够业务复杂度支撑。

### 2. 用模型级只读策略，而非仅隐藏表单字段

为追溯模型统一实现只读 Admin 基类或等价策略：允许 view/list/change-detail 访问，但拒绝 add、change、delete 和批量删除权限；所有内联也只读。只将 `PolicyVersion` 与 `PolicyRule` 注册为可编辑配置模型。`ManagedGame` 不允许手工编辑，唯一写入口是既有“从受控微信同步可管理游戏”动作。

仅使用 `readonly_fields` 不足以阻止新增、删除、批量操作或未来字段遗漏，因此必须同时覆盖 `has_add_permission`、`has_change_permission`、`has_delete_permission` 以及默认批量删除动作。替代方案是完全隐藏追溯模型；这会损失排障、审计和数据核验能力。

### 3. Admin 仅负责追溯，不负责审核与上游写入

删除 `ReviewTaskAdmin` 的受保护处置 URL、操作按钮和确认模板入口。审核任务、AI 评估、回复草案、审计记录和后台任务在 Admin 中仅展示关联、时间、状态和摘要；涉及帖子时提供跳转到内容管理工作台对应 `topic_id` 的链接。

选择单一处置入口能够保证默认原因、二次确认、状态回读、AI 推荐呈现和批量操作使用同一套流程。替代方案是保留 Admin 的应急操作，但会重新引入两套行为与审计语义，且违背“人工处置统一工作台”的产品边界。

### 4. 首页按“配置”与“运行追溯”分层

Admin 首页将配置类入口与只读追溯类入口分区展示，并明确标注只读状态和数据用途。列表页保留对运营有价值的搜索、筛选、日期和关联跳转，删除无意义的默认“新增”按钮。模型名称与说明使用中文业务术语，避免技术表名直接成为运营导航。

### 5. 策略基线与渐进式规则说明

提供幂等命令初始化一套可编辑的通用审核策略；命令不得覆盖已有规则，且仅当不存在其他启用策略时启用该版本。默认策略覆盖通用违规、无关内容、负面灌水、交易风险和内容异常，并且仍只产生人工审核建议。

首页只默认展示启用策略名称、版本与规则数量，避免完整规则占据配置台主体。运营人员可展开规则摘要查看中文风险类型、最低置信度、建议动作和优先级；规则编辑列表同时显示稳定的风险编码及其中文释义。规则摘要必须是响应式布局，不得要求横向滚动。

## Risks / Trade-offs

- [只读 Admin 影响临时修数] → 不提供绕过路径；修复应通过受控同步、重新入队或专门维护命令完成，保留审计一致性。
- [覆盖 Django Admin 模板可能随框架升级变化] → 只覆盖稳定的 `base_site`、`index` 与静态 CSS，不复制完整 Django 模板。
- [策略仍可被直接修改] → 明确将其归为配置能力，并在列表和详情展示启用状态、版本与创建时间；更严格的审批留作后续变更。
- [默认策略被误认为自动处置] → 首页和文档明确其只提供人工审核建议；上游写入仍受工作台人工确认和运行开关约束。
- [现有书签指向 Admin 处置 URL] → 移除入口后返回只读详情或 404；文档和首页导航统一引导到内容管理工作台。

## Migration Plan

1. 添加 Admin 外壳模板、样式和中文信息架构，不涉及迁移。
2. 引入只读 Admin 策略并应用于追溯模型；保留策略配置和游戏同步动作。
3. 删除 ReviewTask Admin 的处置 URL 与操作模板引用，添加工作台跳转链接。
4. 添加 Admin 访问边界与页面渲染测试，收集静态资源后重启 Web 服务。
5. 回滚时仅撤销代码和静态资源；数据库与运行数据不受影响。

## Open Questions

- 无。首版先以策略版本和规则作为唯一可编辑配置，后续通过实际使用反馈决定是否需要更细的策略发布流程。
