## 背景与约束

游戏圈粉丝、内容消费、内容创作、内容分享和游戏圈活跃用户按日更新，后台标示为每日 `07:00` 更新；运营效果按周更新，后台标示为每周一 `17:00` 更新。Scheduler 分别在 `07:30` 和周一 `17:30` 后入队，为上游落稳预留 30 分钟。

受控 Chrome 登录态通常在约 `04:00` 失效，运营人员约 `09:30` 扫码恢复。任务必须锁定原业务日期并等待人工恢复；不得自动登录、保存凭据或因为未登录写入零值。

内容分析详情支持日期范围，只返回实际存在的日期记录，且 `desc_order=false` 不能保证升序。留存标签的 `7/14/30` 是查询窗口；目前仅验证到 `quanzi_dau`（游戏圈活跃用户），不得将其命名或计算为留存率。

## 目标与非目标

### 目标

- 用同一稳定模型保存单游戏、单来源、单业务日或周的聚合数据。
- 支持按日期块回填、按返回 `ds` 非连续落库、分页恢复和确定的短窗口复核。
- 在工作台明确数据日期，避免将不同来源的不同业务日误作横向比较。
- 对登录、权限、契约和临时上游故障提供可追溯且不污染历史的处理。

### 非目标

- 不持久化排名、能力卡、配置、同类参照、作者或认证账号明细。
- 不保存原始响应、token、Cookie、完整认证 URL 或认证账号标识。
- 不展示或保存未经验证的 7/14/30 日留存率。
- 内容粉丝未取得成功权限与字段样本前，不创建任何生产采集任务。

## 快照模型与来源注册

`GameCircleMetricSnapshot` 的稳定业务键为：

```text
(appid, source, period_start, period_end, scope)
```

`scope` 首期固定为 `ALL`。一行只保存该来源的白名单扁平指标、`captured_at` 和最近任务；同一业务键同步只更新该行。

| source | 周期 | 上游来源/开关 | 白名单指标 | 启用状态 |
| --- | --- | --- | --- | --- |
| `CIRCLE_FANS_DAILY` | 日 | 游戏圈粉丝详情 | 粉丝存量、新增、退圈 | 启用 |
| `GROUP_CONSUME_DAILY` | 日 | `need_content_consume_data` | `daily_active_user`、`content_consume_cnt` | 启用 |
| `GROUP_PUBLISH_DAILY` | 日 | `need_content_publish_data` | `publish_pv`、`publish_uv` | 启用 |
| `GROUP_SHARE_DAILY` | 日 | `need_content_share_data` | `share_cnt`、`share_uv` | 启用 |
| `GROUP_RETAIN_DAILY` | 日 | `need_content_retain_data` | `quanzi_dau`，展示名为游戏圈活跃用户 | 启用 |
| `CONTENT_FANS_DAILY` | 日 | 内容粉丝详情 | 取得权限后另行确定 | 禁用 |
| `OPERATION_EFFECT_WEEKLY` | 周 | 运营效果详情 | 已验证的运营效果周字段 | 启用 |

来源之间即使字段同名也不得混写。`CONTENT_FANS_DAILY` 可保留枚举和受控失败语义，但不得注册到 Scheduler 或人工生产回填入口。

## 内容分析读取与恢复

内容分析使用：

```text
GET /cgi-bin/gameopenmpwap/cfcommcgi/spacexgamemp_datacenter_getgroupconsumedetaildata
```

请求 `data` 包含 `start_ds`、`end_ds`、`desc_order`、`cur_page`、`per_page` 和四个互斥 `need_*_data` 开关之一。来源注册表是 source 与唯一开关、白名单字段、解析器的唯一映射位置。

读取过程：

1. 按 source 和最多 90 个自然日的日期块请求；每页最多使用已验证安全值 `366`，不得假设单页足够。
2. 校验成功业务码、`data.list`、每条有效 `ds` 和当前 source 必需字段；`data.total_count` 仅作分页辅助，因为内容消费/创作/分享实测可在返回记录时仍为 `0`。
3. 显式按 `ds` 排序，以每条记录的 `ds` 写入；范围缺日不写行、不覆盖既有快照。
4. checkpoint 至少含 source、日期块起止、下一页、已保存数量和最后业务日。只有整个页保存后才推进下一页；中断重试该页是允许的，稳定业务键保证幂等。
5. `total_count` 缺失、小于当前页记录数或与短页矛盾时，按“无可靠总数”处理；只有完整页才继续翻页。不得因该字段的统计异常丢弃当前已验证记录。

留存的 7/14/30 切换只改变查询范围。`GROUP_RETAIN_DAILY` 每日只存 `quanzi_dau`，不创建窗口来源或留存率。

## 任务、调度、复核与错误分类

任务类型为 `METRIC_DAILY_SYNC`、`METRIC_WEEKLY_SYNC` 和人工 `METRIC_BACKFILL`。Scheduler 只入队，不建立 CDP 会话、不认领任务。

| 任务 | 调度与范围 | 复核规则 |
| --- | --- | --- |
| 日同步 | 每日 `07:30` 后；五个已启用日 source 各一个稳定调度任务 | 每次读取 `D-2` 至 `D0`，其中 `D0` 是锁定的昨日 |
| 周同步 | 周一 `17:30` 后；运营效果 | 每次读取最近三个已完成周 |
| 人工回填 | 运营人员指定 source 和日期范围 | 按 90 日块和页 checkpoint 恢复；终态后允许新运行批次 |

同一调度时间桶使用稳定幂等键；同一人工语义范围只允许一个 `PENDING`/`RUNNING` 任务，需由数据库约束或租约原子保证。终态人工任务可创建新批次；快照始终按稳定业务键更新。

| 错误类别 | 行为 |
| --- | --- |
| CDP 不可用、未登录、身份绑定失败 | 延后 5 分钟，不增加 retry count，保留业务日期和 checkpoint。 |
| 明确权限不足、不可解析 `ds`、必需字段缺失、结构不兼容 | 终态失败，记录脱敏类别，不写或覆盖任何快照。 |
| HTTP 429、5xx、传输错误 | 最多 3 次指数退避，单次延迟上限 5 分钟；耗尽后终态失败。 |
| 未知非零业务码 | 至少重试 1 次；仍出现则终态失败并记录脱敏业务码。 |

每日稳定任务若终态失败，当日重复 Scheduler 检查不得创建重复任务；运营人员可创建人工复核批次，且下一日的 `D-2` 至 `D0` 自动复核仍可修订该业务日。

## 工作台与数据日期

工作台分为每日运营和周度复盘；帖子实时分析保留为独立的辅助分析，不得替代游戏圈聚合快照。

每日首屏的共同口径是五个启用日 source 都返回记录的**最近完整业务日**。该日期用于跨域并列的粉丝、创作、消费、分享和活跃用户 KPI。

- 存在最近完整业务日时，所有首屏日 KPI 必须使用该日，页头显示该共同业务日。
- 不存在完整业务日时，页面必须显示“不完整日数据”，每张卡标出自己的 `ds` 或“缺失”；不得生成跨域环比、漏斗转化或综合健康判断。
- 各 source 的趋势可各自按 `ds` 绘制，图例/卡片必须标示来源和数据日期；趋势异常只比较同一 source 的相邻已落库日。
- 周度复盘只显示周快照和周起止日期，不与日 KPI 混排。

每日首屏指标：粉丝存量/新增/退圈/净增，发帖数/创作人数，访问用户/浏览量，分享次数/分享人数，游戏圈活跃用户。周度首屏指标：日均访问、渗透、触达新进/月回流/付费用户、发表率、优质内容率、服务分发曝光/点击。

排名、能力卡、配置和同类参照仅是诊断层，不进入首屏 KPI，也不在本 change 中持久化。

## 取舍与最小验证

- 仅抓昨日：无法回填和修订迟到值；拒绝。
- 按请求日期补零：会把无记录误解为零；拒绝。
- 同一日来源合为单一 source：丢失字段契约和错误定位；拒绝。
- 逐卡展示最新值但不显示日期：容易跨日误判；拒绝。
- 所有非零业务码立即终态：会把短暂限流或上游抖动变成漏数；拒绝。

最小验证：

1. 已登录受控 Chrome 下，以不少于 30 天范围分别验证四个内容分析开关；确认唯一开关、字段结构、非连续 `ds`、排序和缺日不补零。
2. 模拟分页中断、登录失效、429/5xx、未知业务码、权限与契约错误，确认 checkpoint、重试计数和终态分类符合表格。
3. 构造五来源同日完整和其中一源缺失两组快照，确认首屏共同日期或逐卡日期/不完整提示，且不产生跨日比较。
4. 同时触发两个相同人工回填请求，确认只存在一个活跃任务；终态后新批次可更新同一稳定快照。

## 周度发布稳定性

运营效果接口的 HTTP 成功和记录字段齐全不等于数据已经完成发布：已观察到同一完整业务周先返回全零、后返回有效聚合值。周快照因此新增发布状态 `VERIFIED` 与 `PENDING_RECHECK`；日来源固定为 `VERIFIED`。周度工作台只读取 `VERIFIED` 快照，待复核记录仅作为时效提示，不得展示为经营结果。

### 判定与覆盖规则

运营效果的核心指标为日均访问、游戏圈渗透、内容曝光、触达新进/回流/付费用户、发表率和优质内容率；好友动态曝光与点击允许自然为零，不参与占位判定。若一条运营效果记录的全部核心指标为零，则记为 `PENDING_RECHECK`：

- 该业务周没有既有快照时，保存脱敏的白名单数值和待复核状态，保留任务追溯；
- 已有 `VERIFIED` 快照时，不改写其指标、采集时间或发布状态；
- 任一核心指标非零时，按稳定业务键写入并标记 `VERIFIED`，从而覆盖同周期的待复核记录；
- 真正全零的周在后续复核仍保持待复核，而不是猜测为有效零；运营人员可从工作台和任务记录识别为待上游确认。

选择状态化快照而不是“遇零直接丢弃”：后者会丢失可追溯的接口观察；选择状态化而不是以单次延时 sleep 处理：上游稳定时间和扫码恢复时间并不恒定，固定复核桶可在重启后幂等补齐。

实现边界由两个领域模块集中承担：`weekly_publication` 是核心指标集合、发布状态判定和展示资格的唯一来源；`weekly_schedule` 是发布阶段与业务周映射的唯一来源。`metric_sync` 仅负责来源 DTO 校验和通过该策略写入稳定业务键，`metric_jobs` 仅把调度计划转换为任务，`services` 仅消费已验证状态。这避免将同一“全零占位”判断复制到 Worker、Scheduler 和页面分支中。

### 周度复核桶

Scheduler 对同一已完成周使用三个彼此独立、稳定幂等的发布桶：周一 `17:30` 初始读取、周二 `10:00` 上午复核、周二 `16:00` 下午复核。每个桶读取最近三个已完成周；业务周在三个桶中保持不变。Scheduler 在晚启动时必须为当前周已经错过的桶补入任务，同桶重复检查不得重复入队。登录失效仍复用既有 5 分钟延后策略。

这比只在周一单点读取多两次发布后机会，且上午复核安排在正常扫码到岗之后。最近三个周的范围使近期迟到数据可在下一周继续得到修订。

### 迁移、展示与回填

迁移为既有快照补默认 `VERIFIED`，并将所有核心指标全零的历史周记录降为 `PENDING_RECHECK`。这不会删除指标或原任务关联，回滚仅移除状态字段；回滚前需停止依赖该字段的新 Worker 与页面代码。

工作台使用最近一条 `VERIFIED` 周快照渲染卡片和趋势；若存在更新的 `PENDING_RECHECK` 周，周度面板显示该周“待上游稳定性复核”，并禁止将其 0 值加入表格、趋势或告警。已确认受影响周通过既有人工范围回填任务重新读取，不保存原始响应。

最小验证：构造全零核心指标、已验证非零快照与后续有效返回，确认全零不覆盖、后续有效值可覆盖；验证三个调度桶的独立幂等和晚启动补入；验证工作台只显示已验证周并提示待复核；在已授权受控 Chrome 下重新读取 2026-07-13 至 2026-07-19，确认其转为 `VERIFIED`。

## 指标工作台的运营阅读模型

工作台服务于值班运营而非数据录入：页面先回答“今天发生了什么”，再给出需处理的异常，再支持按单一业务口径探索趋势，最后提供周度复盘和内容运营辅助信息。装饰性说明文字、英文眉标题和分散的规则注释会与状态、日期和指标竞争注意力，删除；数据截至日期、待复核状态、卡片的新增/退圈/净增与异常原因是决策依据，保留。

### 信息架构

1. 标题、完整业务日与紧凑筛选在同一顶部工作条中；仅一个可管理游戏时不强调游戏选择。
2. 五张每日 KPI 卡先展示当前值和相对上一完整业务日的变化，卡片内保留粉丝新增/退圈/净增等必要拆解。
3. “异常与待行动”紧随 KPI，按来源指标给出可追溯的异常文本；内容审核和互动刷新移至页面末尾的辅助区。
4. 粉丝增长、每日运营指标和运营效果复盘组成主分析区。周度状态是标题标签，而不是额外占据面板高度的提示条。

### 视图模型与交互

视图选择、指标元数据、图表坐标和无数据语义由专用的指标工作台读模型生成，模板只负责渲染，不在模板/CSS/JavaScript 中计算数据。图表使用内联 SVG，不引入外部图表库、CDN 或浏览器端上游请求。

- 粉丝增长默认图表、可切换明细；图表为粉丝总量折线，并在每个业务日保留原生悬停提示中的新增、退圈和净增。
- 每日运营默认图表、可切换表格；图表一次只展示一个可选择的业务指标（粉丝、创作、消费、分享、活跃用户），不得把不同量纲压到同一坐标轴中。表格保留所有口径，作为核数视图。
- 每日运营图表改为多序列比较：指标 Tab 是可多选显示开关，图表至少保留一个来源。实际值模式以当前选择的全部序列的真实最小/最大值动态计算共用坐标轴；趋势指数模式将每个序列的首个有效值设为 100，用于跨量级比较涨跌。悬停始终显示真实值，不把指数误作经营绝对值。
- 两组切换均采用 GET 参数与可访问链接，保留日期和游戏范围；默认图表但不写入用户画像或偏好数据。
- 同一日期范围内的图表、明细表和五个单指标日图一次由本地快照读模型生成；页面加载后切换只改变已渲染面板和地址栏查询状态，不得触发整页导航、滚动复位或任何上游请求。无 JavaScript 时，链接仍以 GET 请求提供可访问回退。
- 图表按来源自身已落库日期绘制，业务日期缺口必须断线，不能用相邻点连成虚假的连续趋势。

最小验证：给定连续和缺日的粉丝/日来源快照，验证 SVG 点位、断线、悬停文本与表格均只来自本地快照；验证两个切换保留日期、游戏与彼此视图状态；验证默认图表、单指标选择及不完整日不产生跨域判断。

多序列控制必须将“显示哪些指标”和“以何种方式比较”分为两个具名控件组：前者使用可见的多选勾选状态和“至少保留一项”说明，后者使用单选的实际值/趋势指数分段控件。不得将多选指标伪装成互斥 Tab。

内容审核摘要与互动刷新是同一辅助工作流，页面 SHALL 将其合并为一个“内容运营辅助”模块：状态摘要采用紧凑网格，刷新是右侧唯一明确操作；不得以两张等宽主卡片分割。无异常时，“异常与待行动”收缩为单行健康状态。多序列图必须输出带颜色的图例和基于所选范围的首/中/末日期刻度；KPI 环比作为固定的状态标签而非弱化的小字。

图表悬停采用自定义浮层而非浏览器原生标题：命中任意数据点时显示该业务日期和全部可见序列的真实值，并以垂直定位线关联图形；命中区域必须大于可见圆点。

顶部日期工具命名为“统计周期”，影响整个工作台，且不提供“今天”快捷项，因为每日指标以 D-1 发布。每日运营面板标题显示当前统计周期和已落库业务日数；图中显示指标与统计周期分离。实际值纵轴固定从 0 起、上界按所选数据动态扩展；趋势指数纵轴保持自适应。

工作台最终信息层级为：单行统计周期工具条、主次分层的每日经营 KPI、最高优先级异常行动、趋势解释、低干扰的内容运营辅助。快捷周期与手动日期属于同一表单；手动日期不匹配预设范围时不显示预设选中态。异常区只展开最高优先级异常，其余通过“还有 N 项”进入详情，健康状态收为单行。KPI 将粉丝、内容消费、活跃用户作为主要判断，创作和分享作为次要指标。图表控件即时生效且不保留额外确认按钮；每个图都显示范围、业务日数、图例、日期刻度与真实值提示。内容运营辅助使用弱化的收尾样式，不与主行动竞争。

顶部 KPI 采用所选统计周期汇总而非范围内最近单日快照：粉丝显示期末存量及期间新增、退圈、净增；创作、消费、分享显示期间累计；游戏圈活跃用户显示已落库日均。数据截至日独立显示，不得暗示卡片为单日值。

行动提醒必须展示来源、两个实际业务日、前后数值、绝对变化和百分比变化；只有下降达到 5% 的指标进入待关注列表，低于阈值的普通日波动不标为异常。提醒附带与该指标相关的下一步建议，不要求运营人员猜测告警所指内容。
