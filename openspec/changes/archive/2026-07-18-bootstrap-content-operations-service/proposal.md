## 背景与目标

游戏圈内容运营需要从大量候选帖子中筛出原创帖，并以 AI 建议辅助人工完成审核、处置和反馈回复。原平台混合了原创帖与转发评论帖，且正文、图片、视频、投票标题和选项都可能承载违规传播信息；平台还需要可追溯地处理沉底、屏蔽、禁言、解除禁言和恢复正常。

现在先建立 Django 单体服务框架，能够在不建设独立前端的前提下承载后续采集、AI 评估、人工操作和日报能力，并为原平台私有接口的受控接入预留边界。

## 变更内容

- 创建 Python 3.12 + Django 5.2 LTS 单体服务，以 Django Templates 的“队列 + 详情”工作台作为帖子运营入口，Django Admin 仅用于账号与系统配置。
- 配置 SQLite 数据库、迁移、WAL 运行参数和基础健康检查；不引入 Redis、Celery 或独立前端。
- 建立原创帖子、AI 评估、人工审核任务、人工操作审计、日报指标和持久化后台任务的数据模型。
- 建立服务层接口与后台任务编排，支持原创判定、AI 评估、人工处置、回复建议和日报。
- 明确所有原平台写操作只能经人工确认发起；系统不得自动沉底、屏蔽、禁言或发布回复。
- 为沉底、屏蔽、禁言、解除禁言和恢复正常提供经验证的 CDP 写适配器；每项能力由独立开关控制，默认关闭，且只有人工二次确认才能调用。
- 提供原平台与 AI/OCR 的适配器边界、配置管理、结构化日志和测试基础，避免会话令牌或 Cookie 进入持久化业务数据。

## 能力范围

### 新增能力

- `service-foundation`: Django 单体服务、SQLite 配置、迁移、健康检查、管理后台和运行时配置基础。
- `original-post-ingestion`: 原创帖数据模型、投票文本、业务删除状态、来源状态、可断点的采集任务与原创判定服务契约。
- `ai-review-workflow`: AI 评估结果、审核队列、回复建议、人工确认处置、状态回读和操作审计契约。
- `daily-operations-reporting`: 原创帖、内容分类、风险建议、人工处置和回复建议的每日聚合指标。

### 修改的能力

无。当前没有已发布的 OpenSpec 能力规格。

## 影响范围

- 新增 Django 项目、领域应用、数据库迁移、后台 Worker/Scheduler 管理命令和基础测试。
- 新增依赖：Django、HTTP 客户端、Pydantic、结构化日志、测试与代码质量工具；OCR 与具体 AI SDK 保持在可替换适配器后。
- SQLite 文件需要作为受控持久化卷运行，首期限定单 Web 实例和单后台 Worker。
- 后续原平台读取/写入接口与 AI 服务只能通过适配器调用；凭据仅由运行时环境变量或密钥存储提供。
