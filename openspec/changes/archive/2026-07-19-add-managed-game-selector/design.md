## Context

帖子已按 `source_appid` 归属，但工作台把游戏作为本地 AppID 多选筛选项，且无法展示账号可管理游戏名称。已验证的 `getWxaList` 只能在登录后的 `mp.weixin.qq.com` 外层页面调用；当前 CDP 实现只定位 `gamemp.weixin.qq.com` iframe。

## Goals / Non-Goals

**Goals:**

- 以“城主别慌张”为缺省单选游戏范围，明确工作台管理对象。
- 持久化上次成功同步的游戏名称，登录失效时仍可使用工作台。
- 仅人工触发读取上游游戏列表，不让页面渲染、scheduler 或 Worker 依赖该接口。

**Non-Goals:**

- 不提供“全部游戏”或多选游戏范围。
- 不随游戏切换自动采集、修改自动调度配置或执行上游写操作。
- 不持久化公众平台 token、Cookie、完整认证 URL 或运营者身份。

## Decisions

### 本地目录为唯一渲染来源

新增 `ManagedGame`，以 AppID 为唯一键保存名称和最近成功同步时间。迁移预置城主别慌张；页面只读本地目录，并将已有帖子中未知 AppID 以降级名称补充显示。这样登录失效和 CDP 不可用都不影响阅读本地帖子。

### 单选查询参数作为工作台上下文

`appid` 仅允许一个有效值。缺失、空值或不在目录中的值回退至默认 AppID；工作台帖子、统计、筛选、导航均按该值限制。筛选栏移除游戏控件，标题旁选择器负责切换，切换会重置当前 `topic` 但保留其他筛选参数。

### 同步由 Admin 显式动作触发

管理员在 `ManagedGame` 的 Django Admin 列表中显式执行“从受控微信同步可管理游戏”动作。适配器只在 `mp.weixin.qq.com` 页面 isolated world 内读取当前 URL 中临时 token 并发起 `getWxaList`；返回值立即标准化为 AppID 和名称。成功时 upsert，失败时返回脱敏消息且不删除缓存。工作台不发起上游游戏目录请求。

## Risks / Trade-offs

- [外层页面结构或列表字段变化] → 适配器抛出契约错误，保留缓存并以测试固定 DTO。
- [当前会话失效] → 同步失败不改变缓存，工作台继续默认或使用已选游戏。
- [未知历史 AppID] → 以 AppID 作为降级名称显示，避免隐藏已有帖子。
- [用户误以为切换会采集其他游戏] → UI 明示“当前工作台范围”；自动采集文档继续注明仅城主别慌张。
