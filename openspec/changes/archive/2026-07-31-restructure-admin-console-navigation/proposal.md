## Why

系统配置页已经包含完整的运行、自动任务、核心配置、运行健康和数据追溯能力。问题不在于能力需要拆走，而在于长页中缺少稳定的阅读定位：用户需要反复滚动才能在保留上下文的同时回到需要的区块。

此前将该问题扩大为首页重组、专项工作区、Admin 侧栏与顶栏健康请求，改变了原有操作面和发现路径，超出了“优化当前页面”的目标。本 change 改为一次局部、可逆的导航与层级优化。

## What Changes

- 保留 `/admin/` 的既有 Hero、运行概览、当前操作游戏、流程/服务双视图、自动任务生产者、核心配置、运行健康和数据追溯；不迁移、不删除、不复制任何现有操作入口。
- 为既有五个主区块增加稳定语义锚点；仅在正文外留白足够的超宽屏提供 Wiki 式外置固定“本页目录”，其余视口在 Hero 后使用原生 `<details>` 展开目录。
- 将五个主区块收敛为原生披露区：运行概览默认展开，自动任务生产者、核心配置、运行健康和数据追溯默认收起；Hero 始终保留，外置目录仅在不侵占正文时出现。
- 目录点击或直接访问已有 fragment 时，页面仅展开对应披露区再定位；不监听滚动、不自动展开阅读途中经过的区块，也不保存区块展开偏好。
- 目录只链接当前页面的运行概览、自动任务、核心配置、运行健康和数据追溯；不包含跨页面入口、服务状态、操作按钮或表单。
- 系统配置沿用所有运营页面共用的顶栏响应式规则；顶栏禁止换行，在视口宽度不大于 `1080px` 时隐藏主导航，保留品牌、主题切换和会话状态，不以 Admin 专属样式强制导航换行。
- 仅整理现有页面的标题层级、锚点焦点偏移、区块披露和目录的深浅主题/焦点样式；不引入滚动监听、轮询、异步数据请求或业务状态。

## Delivery Gate

本 change 先交付低保真 UI 方案图，确认信息层级、目录位置、窄屏降级和“目录不承载操作”的边界。只有运营人员明确确认该方案图后，才允许开始模板、CSS、JavaScript 或测试实现；图未确认时，change 保持在设计评审阶段。

## Explicitly Deferred

- Django Admin 侧边栏启用、模型业务域分组与跨页面导航。
- 将系统配置页拆分为仪表板、运行与服务、自动任务等专项工作区。
- 顶栏运行健康聚合、摘要端点、缓存和浏览器异步请求。
- 全局搜索、数据追溯索引页或现有业务页面布局调整。

这些事项各自影响路由、权限、请求成本或现有工作流，必须在独立 change 中重新定义范围、风险与验证，不得作为页内目录的附带改动。

## Impact

- 受影响范围仅限现有 `/admin/` 的模板、对应的共享样式和必要的渲染测试。
- 不新增路由、数据库迁移、模型、Worker、Supervisor 控制、CDP 调用、Job 创建、上游请求或运行配置。
- 高风险最小验证：通过 Django 测试证明目录和披露区不增加或移动 POST 表单、CSRF token、服务控制和 Job 创建入口；浏览器验收只进行 GET、区块展开/收起、目录定位和主题切换。
