## Context

`/admin/` 是当前系统配置的完整操作面。其正文顺序已经反映实际运营路径：先查看运行与当前操作游戏，再处理自动任务和配置，最后查看健康与追溯。该页面包含受 CSRF 保护的服务控制、目录同步、游戏切换、生产者管理和运行配置表单；这些入口的 URL、权限、反馈与回跳已经被现有用户流程依赖。

本次只解决长页定位。不得以“目录”为由把区块迁移到新页面、改变表单归属，或把跨页面功能混入页内导航。

## Goals

1. 在不改变正文顺序和业务能力的前提下，让运营人员能快速定位现有主区块。
2. 让目录的职责一眼可辨：它是当前文章式长页的阅读辅助，不是系统导航、服务状态条或快捷操作区。
3. 在桌面、窄屏、浅色、深色和无 JavaScript 情况下保持可用、可读且无副作用。

## Non-goals

- 不启用或重构 Django Admin 侧栏；当前共享顶栏与现有 Admin 模板结构保持不变。
- 不拆分 `/admin/`，不新增 `/admin/runtime/`、`/admin/automation/` 或其他专项 GET 入口。
- 不修改 `admin_console_overview`、运行快照、Supervisor 读取、会话/Frame 状态、Worker、Scheduler 或 Job 生命周期。
- 不增加运行健康 API、缓存、轮询、WebSocket、浏览器后台请求或全局搜索。
- 不调整内容管理、禁言管理、AI 操作复审、运营分析或舆情报告页面。

## Information Architecture

页面保留以下阅读和操作顺序：

```text
系统配置与追溯台
├─ 运行概览
│  ├─ 当前操作游戏
│  └─ 按运行流程 / 按服务管理
├─ 自动任务生产者
├─ 核心配置
├─ 运行健康
└─ 数据追溯
```

目录仅列出与主区块一一对应的五项：运行概览、自动任务、核心配置、运行健康、数据追溯。“当前操作游戏”属于运行概览内部，不单独占用一个目录层级；流程与服务视图也不成为跨页面或跨区域导航。

## Visual Approval Gate

[`ui-proposal.svg`](ui-proposal.svg) 是本 change 的低保真视觉基线，包含宽屏与窄屏两种状态。它用于确认以下不可变决策：

- Hero 和正文保持原顺序；目录只在超宽屏移到正文最大宽度之外的右侧留白，不参与正文布局。
- 目录只列五个正文主区块，且与服务卡、表单、dialog 和跨页面入口分离。
- 所有非超宽屏只保留 Hero 后的原生可展开目录，正文保持完整可用宽度。
- 方案图刻意不展示新增服务状态、按钮或页面路由；它们不属于本 change。

[`ui-section-disclosure.svg`](ui-section-disclosure.svg) 补充确认正文的默认可见性与目录跳转结果：Hero 常驻；运行概览默认展开；其余四个区块默认收起；目录跳转只展开目标区块后定位。图中的目录仅表达超宽屏外置目录的交互关系；非超宽屏改用 Hero 后的原生折叠目录。

该资产不是生产 HTML 或视觉定稿。必须由运营人员明确确认结构和布局后，才允许执行任务 1.1 及后续实现；未确认时只能修改方案图、设计与规格，禁止改动应用代码。

## Interaction and Layout

### Shared top bar

- 系统配置与内容管理、AI 操作复审、运营分析和舆情报告共用同一个 `topbar.html`、主题切换脚本与顶栏响应式规则。
- 共享顶栏必须显式固定为横向 flex 布局并禁止换行，以覆盖 Django Admin 在 `≤1024px` 时对通用 `#header` 施加的纵向布局；在视口宽度不大于 `1080px` 时，系统配置必须与其他 Tab 一样隐藏主导航，保留品牌、主题开关和会话状态在单行内。该阈值高于正文的手机断点，用于避免中等宽度下品牌、导航和会话状态互相挤压；不得由 `admin_console.css` 强制主导航显示、换行或挤压右侧状态。
- 共享顶栏必须在浅色与深色主题中显式定义品牌、普通导航、激活导航和账户链接颜色，且选择器优先级必须覆盖 Django Admin 的基础 `#header` 链接规则。
- `admin_console.css` 不得重新定义共享顶栏的布局、间距、导航显示规则或主题开关交互；系统配置的正文视觉仍可使用其既有色彩 token。

### Section disclosure

- 五个主区块均使用原生 `<details>` / `<summary>`。摘要是该区块唯一的展开或收起入口，显示标题、简短说明和明确的展开状态；它不得承载表单、服务控制、跨页面入口或诊断操作。
- 运行概览默认带 `open` 属性，避免首页首次进入时隐藏当前操作游戏、会话/Frame 状态和恢复方向。自动任务、核心配置、运行健康和数据追溯不带 `open` 属性，降低长页首屏密度。
- 披露区的 id 就是既有五个 fragment 锚点；不得新增第二套锚点、复制正文或移动任何正文元素。目标的 `:target` 反馈施加于整个披露区而非内部卡片。
- 目录链接和 hash 协调脚本仅在显式定位时展开目标区块：目录链接点击、初次加载含 hash、或 `hashchange`（浏览器前进/后退）。脚本不得监听 `scroll`，不得根据视口位置改写任何区块的 `open`，不得使用 localStorage/sessionStorage，也不得调用 fetch。
- JavaScript 不可用时，目录仍是普通 fragment 链接，披露区仍是可手动操作的原生 `<details>`。带 hash 的链接可能只定位到收起摘要；这是无脚本模式下保留原生可用性的可接受降级。

### Ultra-wide screens

- 保持现有绿色 Hero 的完整视觉框、内容和正文先后顺序；系统配置正文最大宽度收敛为 `1200px`，Hero 与正文在该阅读列内横跨完整可用宽度，目录不得侵占、切分或压缩它们。共享顶栏仍保持共用的 `1320px` 对齐基线，不改变主题开关尺寸或响应式规则。
- 仅在视口宽度不小于 `1440px` 时，将目录固定在正文最大宽度外侧的右侧留白：目录宽度为 `100px`，与正文最小间距为 `12px`、外侧安全留白为 `8px`；其右边界随 `max(8px, (100vw - 1200px) / 2 - 112px)` 计算，保证目录完整落在留白内。目录顶端与共享顶栏错开；不得与 Hero 并列或占用 Hero 首屏。
- 目录必须显示“本页目录”文本，链接使用普通 fragment，例如 `#runtime-overview`；禁止显示服务运行状态、按钮、表单、跨页面链接或诊断信息。
- 本 change 不实现滚动监听或“当前区块”脚本状态机。用户点击目录时，页面只展开目标原生披露区、更新 fragment 并定位；目标区块可使用 `:target` 获得可见定位反馈。键盘焦点仅由原生链接和 `<summary>` 保持，目录不声明动态“当前项”。
- 正文列必须保留 `min-width: 0`，目录不得参与正文网格或压缩服务卡、表单或对话框。

### Standard and narrow screens

- 在视口宽度小于 `1440px` 时，在 Hero 后、正文前显示原生 `<details>` 目录，默认收起。
- 展开后仍只显示同一组普通 fragment 链接；不得复制正文、操作表单或状态。
- 目录在非超宽屏完全替代外置目录，不占用正文横向空间，并避免任何横向滚动。

### Anchor behavior

- 每个目标区块拥有稳定唯一的 id；锚点定位时必须为固定顶栏留出安全偏移。
- 锚点链接不得额外发起 HTTP 请求、创建 Job、调用 CDP、读取 Supervisor、改变表单值、切换服务或修改配置。页面既有的共享脚本与其请求不属于目录行为，目录不得新增或触发它们。
- 目录本身不控制“按运行流程 / 按服务管理”单选视图。服务分组仍由页面既有视图控件管理，避免目录隐藏额外的状态机。

### Expected interactions

| 用户动作 | 页面响应 | 明确不发生的事 |
| --- | --- | --- |
| 超宽屏点击右侧“核心配置” | 展开既有核心配置区块，地址变为 `#core-configuration`，浏览器滚动至目标；目标获得 `:target` 定位反馈 | 不提交表单、不打开对话框、不读取状态、不切换服务视图，也不额外请求接口。 |
| 超宽屏继续滚动正文 | 外置目录保持在右侧留白；正文和原有操作区域继续按既有顺序显示 | 不追踪滚动、不更新目录状态、不自动展开区块，也不额外发送请求。 |
| 非超宽屏点击“本页目录” | 原生 `<details>` 展开五个普通链接 | 不复制正文、状态或任何操作入口。 |
| 非超宽屏选择“运行健康” | 展开运行健康区块后，浏览器使用 fragment 定位 | 不折叠/展开其他业务区域，不提交任何 POST。 |
| 使用浏览器后退/前进或复制链接 | 带 fragment 的目标区块展开并恢复定位 | 不依赖 localStorage、页面级 JavaScript 状态或新路由。 |

## Accessibility and Visual Contract

- 所有新增图标仅使用仓库既有 Lucide SVG；本 change 不以表情符号或 Unicode 图标充当图标。
- 目录链接和 `summary` 具有可见键盘焦点；目标区块使用 `:target` 定位反馈。系统不实现动态目录当前项。
- 深浅主题复用现有 `data-console-theme` 与 CSS token，不新建存储键或 Admin 专用主题。
- `details`、正文表单和 dialog 的既有层叠关系不得因目录出现而被遮挡。

## Alternatives Considered

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 将首页改为仪表板并拆分专项工作区 | 不采用 | 改变既有操作路径、表单归属和书签，超出导航优化。 |
| 启用 Django 侧栏作为本页目录 | 不采用 | 侧栏应承担跨页面模型入口，不能混同为当前页面 TOC。 |
| 始终显示外置目录 | 不采用 | 常规桌面没有足够侧边留白，目录会压缩或覆盖正文。 |
| 超宽屏外置目录 + 非超宽屏 details | 采用 | 正文始终保持完整宽度；在存在侧边留白时提供 Wiki 式定位，并保留无 JavaScript 回退。 |

## Risks and Minimal Verification

| 风险 | 控制方式 | 最小验证 |
| --- | --- | --- |
| 目录意外复制或移动高风险操作 | 目录模板只含静态 fragment 链接 | Django 渲染测试断言目录内无 `<form>`、POST action、CSRF token 或服务控制 URL。 |
| 外置目录压缩正文或遮挡 dialog | 仅在侧边留白能完整容纳目录时显示；其余宽度退回 Hero 后的 details | 超宽屏、常规桌面和窄屏浏览器截图检查；打开既有 dialog 只观察可读性，不提交。 |
| 主题或焦点回归 | 复用共享 token 和原生元素 | 浅色/深色、键盘焦点与 details 展开只读验收。 |
| 锚点或披露引入隐式业务动作 | 仅允许本地 DOM 的 `open`、fragment 与定位协调 | 测试目录仅含普通链接且脚本无 fetch；浏览器对比点击前后的目录相关请求，确认目录不额外产生 API、POST 或后台请求。 |

## Rollout and Rollback

该优化不涉及数据、配置、服务或路由迁移。发布时仅更新模板与静态 CSS；若目录出现视觉或可访问性问题，移除目录容器与对应样式即可，原页面所有操作继续按原路径运行。
