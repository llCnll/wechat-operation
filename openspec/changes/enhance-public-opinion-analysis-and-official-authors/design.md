## Context

现有 `OriginalPost` 保存标题、HTML、`content_text`、作者 OpenID/昵称与互动快照；`PublicOpinionReport` 在首次运行锁定标题、正文、投票和 AI 快照，并在每个 Run 读取互动快照。报告计算已具备词典热词、议题、情绪、反馈价值、互动榜单和固定运营观察，但不读取日指标，也不调用模型生成结论。当前 `feedback_value` 接受任意非空字符串并显示为“未归类”，无法区分“未填写”和 AI 违反枚举契约。

`ManagedGame` 已是 AppID 到游戏名称的本地目录；作者详情的固定 `getuserdetail` 读取已通过游戏圈会话服务 IPC 提供，响应可携带用户信息和最近帖子。`AuthorMuteStatus` 是禁言状态投影，不能承担官方身份或配置职责。

本变更涉及采集、内容管理、系统配置、报告、AI 调用、Word 导出及作者禁言管理。既有经过人工确认的作者禁言写入保持受控；新增读取仅限运营人员显式发起的平台当前禁言名单分页导入。不得新增无确认上游写入、作者历史批量抓取或评论采集。

## Goals / Non-Goals

**Goals:**

- 将正文尾部话题从可读正文中分离，并使新旧原创帖和报告来源可一致地使用该投影。
- 提供按游戏隔离、可核验且可撤销的官方作者 OpenID 白名单；用关系计算官方身份，而非把可变标签复制进帖子。
- 让报告在锁定内容时固定官方身份、话题和 AI 覆盖质量，在每次 Run 固定日指标和互动指标证据。
- 生成严格可验证、带证据引用和失败降级语义的模型运营结论。
- 统一所有作者禁言入口的覆盖型目标期限写入与写后回读，避免永久续期先解除再禁言造成不必要的短暂放开。
- 让运营人员可将平台当前仍有效的禁言名单以最小字段导入当前游戏禁言管理，而不把远端名单当作全量状态快照。

**Non-Goals:**

- 不把昵称匹配当作 OpenID 核验的等价物；它仅是明确标注的名称匹配规则。
- 不从作者详情分页抓取、保存或回填远端作者历史帖子；预览仅使用该接口单次返回的可见项目。
- 不因官方身份改变帖子状态、AI 自动审核、禁言、上游权限或报告选源规则。
- 不重跑 AI 帖子审核、不分析评论、不将日指标或模型结论用于自动处置、归责或因果判断。
- 不将平台禁言名单缺席解释为解除禁言，不利用该名单修改永久禁言意图、全局禁言、最近来源帖子或本系统禁言审计。

## Decisions

### 1. 以标准化内容分解保存尾部话题

新增一个纯函数，从已提取的可读文本中识别末尾连续的独立话题行。仅完整匹配话题格式的末尾非空行可被抽离；正文中间的 `#`、普通句子、空标签和超过受控长度的文本一律保留在正文。函数返回 `body_text` 与按出现顺序去重的 `topics`，所有采集、单帖刷新和历史回填共用它。

`OriginalPost` 保存独立的话题投影，`content_text` 不再包含被抽离内容；报告来源同时锁定正文和话题，热词/主题分析只使用标题、正文和投票，话题另行聚合。保留 `content_html` 原始最小内容投影，避免因解析规则升级失去可重建输入。

不采用仅在报告页面临时正则分割：那会使内容管理、AI 输入和历史报告出现三套正文语义。也不将话题混入 `ballot_text` 或标题，避免字段用途失真。

### 2. 官方作者是按游戏作用域的独立配置关系

新增 `OfficialAuthor`（名称以实现为准）作为 `(source_appid, openid)` 的唯一、可停用配置记录，保存最近成功核验的昵称、核验时间、创建/停用审计信息；不复用 `AuthorMuteStatus`，不写入作者禁言字段。系统配置的“当前操作游戏”节点提供入口，配置页可选择本地可管理游戏，默认当前操作游戏；选择配置页游戏不改变全局当前操作游戏。

页面“查询作者”通过既有 IPC 对所选 AppID 调用一次固定作者详情读取，校验返回 `data.user.openid` 与输入完全相同后，短暂展示昵称、头像、`total` 和接口首批可见帖子。确认加入只接受尚未过期、绑定 AppID/OpenID/操作者的服务端核验票据，避免把展示请求改写为任意 OpenID 保存；确认不再调用上游。

“移除”实现为停用配置而非删除审计事实：有效白名单立即不再命中，列表不再默认展示；同一 AppID/OpenID 可在新一次核验后重新启用。它不修改任何帖子行。选择硬删除或在 `OriginalPost.is_official` 持久化都会造成历史标签不可解释、批量回写失败或未来采集漏标，因此不采用。

身份计算规则为：同一 `source_appid` 内，已保存作者 OpenID 命中有效白名单时为 `VERIFIED_OFFICIAL`；否则昵称经受控空白标准化后等于 `ManagedGame.name` 时为 `GAME_NAME_MATCH`；其他为 `PLAYER`。OpenID 规则优先且跨 AppID 不得命中。内容管理展示实时计算结果及来源；报告来源在锁定时将结果和值来源冻结，旧 Run 永不被随后配置改写。

### 3. 日指标按来源序列并入 Run，而非构造总分

报告首次锁定只锁定帖子/AI/官方身份/话题与上期帖子基线；`GameCircleMetricSnapshot` 与互动一样在每个 Run 开始时读取。日指标证据只选择当前已启用的日粒度来源、`scope=ALL`、`period_start=period_end`、业务日完整落在报告上海日期范围内且 `publication_state=VERIFIED` 的快照；周指标、跨边界周期和待稳定性复核快照不混入该序列，而以覆盖限制披露。计算器生成带来源、业务日、原始值、采集时点与覆盖/排除原因的证据序列。

存量、日发生量与区间累计的指标不得相加、平均或共同排名。计算器只能在同一指标来源内做相邻可比日的变化；帖子趋势与日指标趋势仅并列呈现，模型只能说“同期变化/未观察到足够数据”，不得输出因果。每 Run 保存实际采用的指标值和快照时间，详情与 Word 不得重新查询当前指标。

不在首次报告锁定时固化日指标，因为互动与指标都属于运行时观察；不直接把 JSON 指标字段暴露给模型，因为不同来源字段语义不同。

报告详情是固定 Run 的展示投影，不得改写 `result_payload`。展示层须将受控反馈枚举键和历史快照中已保存的中文规范值统一映射为同一中文标签；未知值仍视为覆盖缺口。日指标须将 `MetricSource` 映射为中文来源，并将原始指标对象拆成字段名和值的结构化项，采集时间转换为本地可读时间。该投影只影响页面可读性，不改变锁定证据、跨来源不可聚合约束或 Word/模型输入边界。

默认报告应将日指标呈现为“运营指标关联”摘要：每个来源独立展示自身覆盖天数、各原始指标的区间首末值和同口径变化。摘要不得汇总不同来源、构造综合分或暗示与帖子舆情之间存在因果。完整的按日快照仍须保留为可展开的“日指标证据”，供人工核验；它不是主报告的默认阅读路径。

### 4. 反馈价值采用封闭枚举与覆盖缺口

AI 帖子评估的 `feedback_value` 只接受 `NONE`、`LOW`、`MEDIUM`、`HIGH` 或空值；归一化大小写后仍不属于枚举的值为“无效值”，并单独计入报告覆盖缺口。报告不再把无效字符串伪装成业务类别“未归类”。

在锁定报告来源时保存规范化后的有效值及一个无效/缺失状态，不复制异常原文进入默认报告、Word 或日志；受保护来源追溯可保留既有 AI 摘要边界。新评估在模型输出 Schema 校验处拒绝非法值；历史异常值通过报告计算降级，不批量修改历史审核。

### 5. 模型结论消费白名单证据包并可独立降级

确定性计算成功后构造受版本控制的 `ReportConclusionEvidence`：仅含范围、数据质量、已聚合类别/情绪/反馈/风险/话题/热词、日趋势、日指标证据、以及**玩家内容**代表帖的 ID/安全标题/互动值和稳定证据 ID。官方内容代表帖仍是确定性报告的独立展示对象，但不进入模型输入，避免把官方内容互动误读为玩家关注或玩家反馈。证据包不含作者 OpenID、头像、完整正文、评论、认证材料或上游响应。

一个 Run 分为“确定性计算”和“结论生成”两个持久化阶段。前者在短事务中一次性写入指标时点、不可变的内部确定性检查点、数据质量和证据包；该检查点不是对外 `result_payload`，页面、Word 与来源追溯不得渲染它。后续 retry 发现该阶段已完成时 MUST 只读取已保存证据，不得重新读取互动或日指标。结论尝试在外部模型请求前原子登记 `attempted_at` 与输入哈希；进程在该登记后中断时，恢复路径将该 Run 结论收敛为“暂不可用”，而不发送第二次模型请求。终态事务才将确定性检查点与有效结论或“暂不可用”状态组成完整 `result_payload` 并标记 Run 成功。这样每个 Run 最多发起一次模型调用，也不会因为模型阶段中断使同一 Run 的确定性指标漂移或向用户暴露半成品。

报告 Worker 在同一 Run 内完成上述确定性阶段后，以独立的报告结论适配器复用既有受控模型传输配置，但不复用帖子审核提示词、输出模型或策略服务。该适配器请求固定 JSON Schema 的结论。模型输出只能包含至多固定数量的“概览、值得关注变化、人工核验建议、限制说明”，每项以完整、带限定语的一至两句话表达，并至少引用一个证据 ID；服务端验证所有引用存在、禁止动作词/归责/确定因果表述。模型版本、提示词版本、证据 Schema 版本、输入哈希、状态和脱敏错误写入 Run 的结论快照。

若模型调用、JSON 解析或验证失败，Run 仍为 `SUCCEEDED`，确定性结果完整可看，结论区显示“暂不可用”和固定错误分类；不会重试帖子审核、不会自动再次调用模型。人工“重跑”创建新 Run，重新读取互动/日指标并可重新生成结论；已成功 Run 永不覆盖。选择将模型作为报告 Worker 的末段而非 Web 同步请求或新独立 Job，是为了复用报告生命周期与版本边界，且不让失败的摘要阻断报告交付。

模型传输错误在结论适配器边界分类，而非由页面或 Worker 日志猜测。读取超时、连接超时、发送超时、连接失败、鉴权、地址不存在、限流、请求拒绝和服务端错误分别映射为固定代码；页面、Word 与配置页复用同一中文标签。分类不保存上游原始响应或异常字符串，既能区分“增加超时”与“检查密钥”等操作，也不扩大错误信息泄漏面。

### 6. 以算法版本注册表保持报告重跑语义

`PublicOpinionReport.analysis_version` 是执行契约而不只是展示字段。报告 Worker 以版本注册表分派来源输入适配器、确定性计算器、结果 Schema、Word 渲染器和是否存在模型结论阶段。已有 `public-opinion-v1` Report 的重跑继续使用其已发布的 v1 计算与导出路径，不读取新字段也不产生模型调用；只有新建的 v2 Report 使用本变更的能力。未知或已移除的版本安全失败，并保留既有成功 Run。

不采用“发布后所有旧 Report 自动使用新算法”的方案：它会在相同 Report 的重跑中改变口径，并可能因新增字段或模型调用改变历史行为。也不将旧 Report 一律禁止重跑，以保持既有保留期内的重跑契约。

### 7. 代表帖按官方身份分组，标题只是展示字段

代表帖继续采用确定性互动总量/互动率规则。结果行同时带锁定的官方身份来源，页面和 Word 按“官方作者（已核验）/官方名称匹配/玩家内容”显示或筛选。标题不作为官方身份判定；没有标题的帖仍可成为任一身份组的代表帖。

固定运营观察须区分玩家与官方内容：只有玩家代表帖可形成“玩家高互动”观察；官方代表帖只可表述为“官方内容互动”，并明确其不构成玩家兴趣或反馈信号。为兼容不可变历史 Run，展示投影可根据既有锁定身份修正旧 `HIGH_INTERACTION` 的文案，但不得改写 `result_payload` 或触发模型调用。

报告详情和 Word 应将受控结论类型、证据 ID 投影为中文标签，并从同一固定 payload 生成简短佐证摘要（如锁定帖子量、覆盖情况、类别/话题前列项、固定日指标数量、仅玩家代表帖数量）。该投影不查询当前数据库或上游，不暴露作者或正文，也不改变模型输入、结论快照或历史 Run；页面以“结论正文 + 引用式证据”层级呈现，避免将英文内部 ID 直接展示给运营人员。

### 8. 作者禁言是目标期限覆盖，而不是状态机式解除再写入

作者范围 `MUTE` 的业务语义是“将当前游戏禁言截止设为本次确认的目标期限”。写前作者详情读取仍只用于身份一致性核验与审计前状态；它不能因为已有有效禁言而跳过本次确认的写入。所有人工内容管理、禁言管理、AI 复审产生的作者禁言，以及永久禁言续期均复用同一作者目标操作边界。

写后只执行一次受限回读序列，不得在同一次确认中重发写入。回读成功条件是当前游戏截止时间与本次目标截止时间在受控平台传播容差内匹配，而不是“截止不早于目标”：后者会把更早操作留下的更长禁言错误地判为本次覆盖成功。`UNMUTE` 仍维持其已有的“确认未禁言即可成功”语义。永久续期对剩余不足阈值或无有效期的作者直接写入新的 30 天目标；失败时保留本地永久意图和失败审计，等待下一轮重新从最新上游状态处理。

不采用“先解除、再禁言”的实现：它扩大了上游写入次数、引入可见的短暂解除窗口，并让解除成功而禁言失败的恢复语义更复杂。也不将“已经禁言”视为幂等成功，因为不同期限是不同的明确操作目标。

### 9. 平台当前禁言名单是只读补充源，不是解除状态的权威全量快照

禁言管理提供显式的 `BLOCKED_USER_LIST_SYNC` Job。Web 请求只创建或复用 Job；`mute_maintenance` Worker 通过游戏圈会话服务在冻结 AppID 范围内读取 `spacexcontent_gamecircletopicmanage_getblockuserlist`。接口经受控实测为 `page=0` 起始，且 `page_size=500` 可完整返回当前 155 条名单。实现从该经过验证的大小请求；若平台明确拒绝该大小，或在 `total > 0` 的首页返回空名单或不足预期条数而不能形成可用页，则按预定义阶梯降至下一个值。同一个 Job 一旦选定可用页大小即写入无身份 checkpoint 并保持不变。

Worker 每页只读取 `total` 与 `blocked_user_list`，将有效 `openid`、可用 `name` 和 `end_date` 投影到 `AuthorMuteStatus(source_appid, openid)`：`end_date` 固定按 `Asia/Shanghai` 解析为当前游戏 `local_muted_until`。它不持久化头像、审批人、违规原因、`source`、`period_type`、原始响应、认证材料或 OpenID 列表 checkpoint；`last_source_post`、`global_muted_until`、`permanent_mute_enabled`、`permanent_mute_set_at`、`permanent_mute_set_by` 与既有本系统审计均不得被该导入修改。

导入只创建或更新当前名单中确实仍有效的作者。名单中未出现的本地作者可能是分页/权限/平台延迟/范围差异所致，因此不得清空其禁言状态、移出列表或取消永久意图。该任务不读取帖子详情或 `getuserdetail`，不调用禁言或解除禁言写接口。同一冻结 AppID 与范围版本的该任务类型最多一个 `PENDING` 或 `RUNNING` Job；checkpoint 仅保存页码、稳定页大小、总数及处理/导入/跳过聚合计数。

最小人工验证必须在测试游戏中完成：先确认接口可接受的最大页大小与第一页 `total`，再创建一次导入 Job，核对列表中新增作者的昵称、当前游戏截止时间和无永久标记；确认过程中抓取的请求均为 GET，且审计/网络记录不含禁言或解除写请求。不得使用生产作者身份、token 或接口原始响应写入测试夹具。

### 10. 报告模型结论拥有独立的配置入口和可解释状态

报告模型结论是报告 Worker 的可选后置阶段，不是 AI 审核策略。因此系统在“舆情报告 Worker”卡片提供与“配置 AI 审核”同级的受认证“配置舆情报告”弹窗，而不是将其隐藏在 `runtime/.env`、混入“配置 AI 审核”弹窗或跳转到新页面。弹窗只维护 `PUBLIC_OPINION_CONCLUSION_ENABLED`，并只读展示既有 AI 连接的服务地址、模型名称和密钥是否已配置；页面不得显示或写入 AI 密钥、服务地址、模型名称或审核策略。

状态由当前配置和最新报告 Run 的固定结论快照共同计算：开关关闭显示“未启用”；开关开启但 AI 连接缺项显示“模型连接未配置”；开关及连接完整时显示“已就绪，可在新 Run 中生成”；最新结论失败时额外展示其固定、脱敏的失败分类。页面不得将旧 Run 的“未启用”误报为当前配置错误，也不得承诺已完成 Run 会自动补写结论。保存开关后只提示并允许重启 `public_opinion_reporting`；新建报告或“重跑固定来源”才会读取新配置并创建新的不可变 Run。

不采用在报告详情直接提供开关或“补写结论”按钮：前者会把运行时配置与不可变结果混在一起，后者会破坏每个 Run 最多一次模型尝试、输入哈希和固定运行时证据的审计边界。

### 11. 按调用用途收敛 CDP 读取页大小

候选帖子列表的页大小是采集 Job 的执行参数，而不是页面显示参数。自动 `SCHEDULED_INGEST_WINDOW`、人工当前窗口 `MANUAL_CURRENT_INGEST_WINDOW` 与显式历史补采 `MANUAL_INGEST_WINDOW` 统一使用 100；入队时将该值写入参数摘要和幂等键，已入队的旧 Job 保持其冻结的 20，不做运行时迁移或参数覆盖。自动采集的运行时配置仍作为受限默认值，但其合法固定值改为 100，避免出现“配置已保存而入队仍为 20”的双重语义。

固定作者详情接口仅需要 `data.user` 完成 OpenID 一致性校验、禁言状态同步和禁言写前/写后回读。请求仍从 `page=0` 开始，但 `page_size` 由 10 收敛为 3；接口返回的主题列表既不作为作者身份来源，也不保存、显示或用于禁言决策。不得为此引入按作者主题列表翻页的逻辑。

本次不调整平台禁言名单的 500→10 自适应阶梯，也不调整日/周指标的 `per_page=366`。前者已有真实 500 条成功记录，后者与日期范围分页和检查点逻辑绑定；混入同一改动会扩大上游契约风险。

最小人工验证仅执行只读 CDP 调用：在当前测试游戏创建一次新的 100 条采集窗口，核对实际 Job 参数、请求参数和成功/确定失败语义；对已保存 OpenID 调用一次作者详情，核对 `data.user.openid`、昵称及禁言字段仍可解析。验证不得执行禁言、解除禁言或其他上游写入，不得将 token 或原始响应写入仓库。

## Risks / Trade-offs

- [尾部话题规则误抽正文] → 仅处理末尾完整独立行、保留 HTML、为解析器与回填提供样例测试和幂等性测试。
- [昵称等于游戏名可能重名或变更] → 明确标记为名称匹配，只有 OpenID 白名单才是已核验官方身份；报告冻结当时来源。
- [作者详情预览滥用会增加上游读取] → 仅显式操作触发、单次固定页大小、短超时、身份回读一致性校验与速率/会话错误的固定提示。
- [日指标字段语义不一致] → 按 `MetricSource` 保留原口径，禁止跨来源聚合和因果推断，并展示缺失/不可比限制。
- [模型幻觉或引用不存在] → 仅供给结构化证据、JSON Schema 和服务端引用校验；不合格输出降级而非展示。
- [模型结论泄漏帖子或作者信息] → 证据包白名单字段、输入哈希审计、输出 Schema 禁止身份/全文字段，Word 仅导出验证后的结论。
- [报告 Worker 在模型调用中断后重取运行时指标或重复调用模型] → 持久化确定性阶段和调用前尝试登记；恢复只完成降级，不重算或重发。
- [新算法覆盖旧 Report 的重跑口径] → 以报告保存的算法版本分派计算与导出；未知版本安全失败。
- [覆盖禁言误把既有更长期限当作本次成功] → 回读比较本次目标截止与受控容差，审计保留写前/写后状态；同一次确认绝不重复写入。
- [导入列表不完整被误当作解除] → 仅对名单成员做加法式最小投影，绝不因缺席清除本地禁言或永久意图。
- [分页参数未经验证造成导入失败或过量请求] → 在测试游戏按固定降级阶梯验证最大页大小，生产任务锁定首个可用值并在每页推进稳定检查点。
- [帖子列表 100 条被平台拒绝或响应不完整] → 只读最小验收必须核对 Job 的冻结参数和完整列表响应；失败任务保留既有检查点/有限重试语义，不静默退回 20，避免配置与实际请求不一致。
- [作者详情缩页遗漏禁言字段] → 仅以 `data.user` 的 OpenID、昵称和禁言字段为验收条件；缺失或身份不一致继续按既有固定契约错误拒绝同步或写入。

## Migration Plan

1. 增加独立官方作者配置、原创帖话题投影和报告来源/运行结果的版本化字段；现有报告 Run 保持只读并以旧算法版本继续可访问。
2. 发布后执行一次可恢复的本地历史话题回填：只处理已有原创帖，复用内容解析器，不访问上游；可重复执行并记录无身份聚合检查点。
3. 新报告使用新算法/证据 Schema；不回写、重算或改写旧报告。必要时运营人员显式新建报告获取新分析。
4. 部署后进行最小验证：以测试 AppID 查询一个作者、验证后加入/移除白名单；用本地固定帖子/日指标生成报告并核对话题、身份分组、指标快照、模型证据引用和模型失败降级；对一个已禁言测试作者执行覆盖期限并核对单次写入及目标回读；再导入平台当前禁言名单并核对最小投影。除该明确的测试禁言覆盖外，不得执行任何上游写入。
5. 回滚时停用官方作者入口和新报告创建入口；现有帖子保留话题投影，已有新报告只读保留。数据库迁移依照发布流程处理，不删除历史报告或配置审计。
