## Context

现有“运营分析”按游戏和日期实时读取 `OriginalPost`、`InteractionSnapshot` 与 AI 审核聚合，明确不持久化分析结果或生成文件。它适合日常看板，但无法给出某次舆情判断所依据的数据范围、生成时点和可复核结论。用户提供的 CSV 脚本方案包含词频、手工情感词典、主题分类、时段与互动榜单；本项目已有规范化数据库，因此不应引入 CSV 作为第二事实来源。

当前系统只采集原创帖及互动计数，不采集评论正文；AI 评估已保存当前内容类别、`sentiment`、`feedback_value` 和风险证据。`OriginalPost.status=2` 是唯一正常状态，其他组合状态均不属于首次选源范围。帖子状态、文本、评估和互动都会在报告创建后发生变化，故“按日期再次查询”不能满足重跑可复核性。

## Goals / Non-Goals

**Goals:**

- 为单一游戏和上海时区日期范围创建可恢复、可观察的本地只读报告任务；默认最近 30 天，允许 1 至 90 天。
- 在首次实际执行时锁定精确帖子成员、分析所需文本和 AI 评估，使重试与重跑始终使用同一范围；例如首次锁定 400 帖，后续运行仍只分析这 400 帖。
- 每次运行按该次运行时点重取互动快照并保存 `metrics_as_of`；成功运行生成不可变版本，不覆盖历史结论。
- 通过受认证页面查看报告历史、来源清单、运行状态与完成详情，并基于指定完成版本即时导出 Word。
- 使用当前 `ReviewTask.assessment` 的 AI 结果作为类别、情绪、反馈价值与风险的唯一主结论；未评估、空情绪或非受支持情绪值均明确计入覆盖缺口。
- 使用版本化本地词典、停用词和 `jieba` 对锁定的标题、正文与投票文本计算主题与相对上一等长周期的热词；不向模型发送报告输入。

**Non-Goals:**

- 不导入 CSV、不解析 CSV BOM 或错位列，不创建第二帖子数据源。
- 不采集、分析或导出评论正文，不推断有效评论率、评论情绪、作者意图、玩家自删原因或“仅自己可见”原因。
- 不执行 CDP、上游读取、上游写入、AI 审核重跑或自动处置；不将负面反馈视为违规内容。
- 不在一期调用大模型生成摘要、预测舆情、验证官方活动，或创建问题处理/回复闭环系统。
- 不保存 Word 文件、原始上游响应、认证材料、作者 OpenID、Cookie、token、视频 URL 或完整原帖正文到 Word；受保护的来源清单仅在本地数据库中保存报告分析需要的文本快照。

## Decisions

### 1. 以“报告范围、来源清单、运行版本”取代单一可变报告记录

采用三层聚合，而不是给单一 `PublicOpinionReport` 追加覆盖字段：

```text
PublicOpinionReport (稳定范围与访问边界)
  1 --- N PublicOpinionReportSource (首次执行锁定的来源清单)
  1 --- N PublicOpinionReportRun (每次执行的不可变结果版本)
                 1 --- 1 BackgroundJob (该次执行的所有权)
```

`PublicOpinionReport` 是业务对象，保存 `source_appid`、上海时区日期闭区间、正常状态规则版本、分析/模板版本、创建者、来源是否已锁定、锁定时间、保留截止时间和当前成功运行引用。它不保存可覆盖的聚合结果，也不以“完成/失败”代替每次运行状态。

`PublicOpinionReportSource` 是报告的不可变来源清单，每行对应一个精确的 `OriginalPost`，保存原始 `topic_id`、稳定排序键、发布时间、标题/正文/投票文本快照、文本指纹、以及计算需要的 AI 快照：类别、情绪、反馈价值、风险摘要和评估版本/更新时间。它不保存作者标识、评论、认证信息或上游载荷。原帖关联仅用于审计导航，报告计算不依赖关联对象仍存在或仍为正常状态。文本字段作为审计副本受到报告权限和保留策略保护，不进入 Word。

`PublicOpinionReportRun` 表示一次执行尝试，保存递增 `run_number`、状态、关联 Job、开始/结束时间、`metrics_as_of`、输入摘要、数据质量、不可变 `result_payload` 和脱敏错误。一次成功运行写入完整结果后即不可修改；失败运行只保存阶段和脱敏错误，绝不保存半成品结果。一个报告可有多个完成版本和失败尝试，默认详情展示最新成功版本，运营人员可切换查看历史版本。

这样可避免两个常见错误：一是重跑重新按日期取数，导致“同一报告”成员漂移；二是直接覆盖结果，让旧 Word、页面和审计结论失去来源。选择关系模型而非在 JSON 中嵌套来源清单，目的是让来源数量、审计权限、删除和完整性约束可查询、可验证。

### 2. 任务创建、首次锁定与重跑状态机

创建请求只冻结意图，不立即在 Web 进程扫描和复制大量文本。它校验当前可管理游戏、日期范围和静态参数，在事务中创建稳定报告和首个 `PublicOpinionReportRun`，再创建唯一关联的 `PUBLIC_OPINION_REPORT` Job。相同报告范围与算法版本在存在待执行或运行中的 Run 时，使用既有 `BackgroundJob.active_coalescing_key` 返回该活跃 Run；该字段的数据库唯一约束是唯一并发闸门，系统不另建活跃范围键。

状态流如下：

```text
创建报告 -> Run PENDING -> Run RUNNING
                         |-- 首次运行：锁定来源清单 -> 计算 -> SUCCEEDED
                         |-- 可恢复本地错误：保留同一 Run/Job，按既有退避重试
                         `-- 不可恢复错误或重试耗尽 -> FAILED

已锁定报告 + “重跑” -> 新 Run PENDING -> RUNNING -> SUCCEEDED / FAILED
```

首次 Worker 实际认领并开始执行时，在短事务内查询 `status=2`、`source_appid`、日期范围内帖子，按 `publish_time, id` 稳定排序，检查 10,000 帖上限并批量写入来源行，随后把报告标记为已锁定。空范围也是合法且可锁定的零行清单，报告可生成“无可分析帖子”的成功结果；超过上限是不可恢复失败，来源不锁定，运营人员需缩小范围后新建报告。

一旦来源锁定，后续自动重试和人工重跑均只读取 `PublicOpinionReportSource`，即使原帖已删除、变为非正常、被编辑或有新帖子加入范围，也不能改变成员、文本或 AI 结论。人工“重跑”创建新 Run 和新 Job，绝不新建来源行、更不覆盖旧 Run。若报告尚未锁定且首个 Run 在锁定前因进程中断，重试可安全继续首次锁定；数据库事务要么完整写入来源清单并置锁定标记，要么完全回滚。

报告 Run 的 Job 使用受限自动重试（例如既有默认上限内的 2 次重试）处理短暂的本地数据库锁、Worker 中断或文档依赖异常。因为来源在首个实际执行时冻结，重试不会把新数据掺入同一分析。不可恢复的输入契约错误、超出上限或来源完整性错误必须直接失败，不消耗重试。每个失败尝试写入脱敏错误和阶段；成功后才原子写入结果并切换“当前成功运行”。

### 3. 来源快照、互动时点与一致性边界

来源清单锁定的是“哪些帖子以及分析其内容/AI 的依据”，不锁定互动计数。首次锁定事务读取每帖当前 AI 评估，并写入以下最小字段：

| 类别 | 固定字段 | 用途 |
| --- | --- | --- |
| 成员 | `topic_id`、排序键、发布时间 | 范围证据、趋势和本地跳转 |
| 文本 | 标题、正文、投票文本、内容指纹 | 热词、主题、人工追溯 |
| AI | 类别、情绪、反馈价值、风险摘要、评估版本/时间 | 类别、情绪、风险与覆盖率 |
| 审计 | 来源锁定时间、原帖关联（可空） | 差异定位，不作为计算依赖 |

每个 Run 开始计算时，在一个短只读事务中以来源行的 `topic_id` 批量查询每帖截至统一 `metrics_as_of` 的最新 `InteractionSnapshot`。事务将互动值与快照采集时间装载到内存；事务结束后计算器只能使用来源行和该内存互动输入，不能回查 `OriginalPost`、AI 或快照表。若同一帖子没有可用互动快照，保留“缺失”，而不是写成零。完成结果固定 `metrics_as_of`、覆盖率和互动快照最早/最晚时间。

相对上期基线也必须可复核。首次锁定时同时选取紧邻上一等长周期、同游戏且 `status=2` 的基线帖子，将其文本和用于热词、主题、情绪比较的 AI 快照写入与来源清单同一受保护的基线集合；后续 Run 复用它，不在重跑时重新选择基线。基线不属于本期成员数，但必须在范围摘要中显示其数量和可用性。

因此，报告的“内容口径”与“指标时点”清楚分离：成员、文本和 AI 为稳定输入；互动为每个运行版本的实时观察。页面、Word 和 API 都必须同时显示 `source_locked_at` 与 `metrics_as_of`，不能把后者误读为内容截点。

### 4. 计算器、固定 Schema 与可解释结论

计算器是纯本地函数，输入为来源文本/AI 快照、固定基线文本和单次运行的互动输入，输出经版本化 Schema 校验的 `result_payload`。它不持有 ORM、请求对象、CDP capability 或导出对象。算法版本、词典版本、最低互动浏览量、最大代表帖数和 Word 模板版本由代码注册并写入 Report/Run，不允许运营人员在页面调整。

- **内容类别、情绪、反馈价值和风险**：仅聚合来源行锁定的 AI 快照。每帖一个主类别；正面、中性、负面只有固定映射；未评估、空值和未知值分别纳入覆盖缺口，绝不以词典补判情绪。
- **议题与热词**：对标题、正文、投票文本执行 `jieba`、游戏词典、主题词典、停用词、数字和平台通用词过滤。主题可多选，必须标注计数可重叠。热词优先显示相对固定上期基线的差异；无基线只显示词频与限制。
- **互动与代表帖**：互动总量为浏览、点赞、回复、分享的可用值；互动率为 `(点赞 + 回复 + 分享) / max(浏览, 1)`，并施加固定最低浏览量。各榜单不超过 10 条，保存 `topic_id`、安全标题截断值、汇总、比率与采集时间，避免结果中复制全文。
- **日趋势与时段**：使用来源行的上海时区发布时间。日趋势保存正常帖数、情绪覆盖量和议题量；小时分布只表示发帖高峰，不能解释为阅读高峰。
- **运营观察**：固定规则最多五条，只引用报告中的覆盖缺口、同口径情绪变化、主题数量或高互动代表帖，并带明确数值与“需人工核验”。不得推断因果、归责或形成自动处置建议。

结果 Schema 至少包括范围与版本、来源数量、数据质量、类别/情绪/风险、议题、热词、趋势、时段、代表帖、运营观察和限制说明。`result_payload` 通过 Schema 验证后与 Run 成功状态在同一事务提交；结果层不写内容全文，全文只保留在来源清单。

### 5. 页面、追溯权限与 Word 导出

工作区包含创建入口、稳定报告列表、报告详情、来源追溯页和运行版本切换。报告列表展示范围、来源是否锁定、最新运行状态、最近成功指标时点和“重跑”入口；报告详情默认展示最新成功 Run，运行中只展示状态和进度，不展示半成品结论。

来源页只对已认证且具有该游戏范围权限的运营人员开放，分页展示锁定时间、`topic_id`、发布时间、内容指纹、文本和锁定 AI 摘要，并可跳转当前本地帖子详情。当前帖不存在或状态变化时，仍可从来源快照核验输入。页面必须显式提示这是历史输入，不能当作当前帖子状态或当前 AI 结论。来源文本不出现在列表、默认报告详情或 Word 中。

Word 导出须指向一个指定的 `SUCCEEDED` Run，不允许隐式取“当前最新”后再重算。导出路由先验证报告、Run 与当前游戏范围的归属，再从该 Run 的 `result_payload` 流式生成 `.docx`。文档包含范围、运行版本、`source_locked_at`、`metrics_as_of`、算法/模板版本、数据质量限制、聚合和代表帖；不查询帖子表，不保存文件，也不包含作者身份、全文、评论、认证上下文或上游载荷。

### 6. 来源保留与删除

锁定全文带来审计价值，也引入存储和最小化保存责任。因此 `PublicOpinionReport` 必须记录明确的保留截止时间（默认由受控配置常量给出，例如 180 天），页面显示该日期。到期删除采用受控的本地管理命令或 Worker 清理：先删除来源文本和基线文本，再删除所有 Run 结果与报告主记录，整个报告为删除单位，不能只删部分来源造成不可解释快照。删除前拒绝新的重跑与 Word 导出；清理日志仅记录报告 ID、数量和原因，不记录文本。

一期不提供面向普通运营人员的任意单帖删除，避免报告成员与结果失配。若法律、合规或用户请求要求提前删除，必须由受权限的管理操作删除整份报告并使其所有版本不可访问，而不是篡改个别来源行。

### 7. Worker、Supervisor 与依赖

新增默认受管的 `public_opinion_reporting` Worker，只认领 `PUBLIC_OPINION_REPORT`。它只连接本地数据库，使用 Supervisor 既有实例租约、日志、启动/停止/重启和恢复语义，不获得会话 IPC capability，不启动浏览器。创建入口在 Worker 停止时仍可入队，但必须说明任务等待 Worker 启动；Web 绝不自行计算或启动 Worker。

将 `jieba` 与 `python-docx` 作为锁定的生产依赖。最大本期帖子数为 10,000，最大代表帖数为各榜单 10 条；范围默认 30 天、最大 90 天。超过日期或数量限制的请求在创建阶段返回固定脱敏原因。选择独立 Worker 而不是 Web 同步生成或复用采集 Worker，是因为报告可能遍历大量文本，且不属于采集/CDP 职责。

## Risks / Trade-offs

- [锁定全文增加本地数据保存量] → 设置保留期、受保护来源页和整份报告删除；Word 与默认详情永不输出全文。
- [首次锁定与重跑语义混淆] → 以 Report/Source/Run 三层模型、显式 `source_locked_at`、`metrics_as_of` 和版本选择消除歧义。
- [AI 覆盖不完整或情绪值不规范] → 单独展示已评估、情绪可用和未覆盖数量；不对缺口补词典结论。
- [互动快照不同步] → 每个 Run 固定 `metrics_as_of`，披露覆盖率与快照时间；不得把缺失写为 0。
- [词典误匹配或常驻词掩盖变化] → 版本化词典、停用词和固定上期基线；报告显示算法版本与“议题可重叠”说明。
- [Worker 中断或本地瞬时错误] → 来源一经锁定即允许有限重试；成功只新建版本，不覆盖历史；失败不写半成品。
- [Word 导出泄露不必要信息] → 仅导出运行结果白名单字段，禁止作者标识、全文、评论和认证上下文；只允许已认证运营人员下载。
- [报告被误读为自动决策] → 报告页面和 Word 固定标注“运营参考”，将负面反馈、风险审核和人工处置分开呈现。

## Migration Plan

1. 增加报告、来源清单、基线清单、运行版本模型、任务类型、Worker、路由、依赖和数据库迁移；不回填历史报告。
2. Supervisor 部署时执行迁移和静态资源采集，并按既有 desired 状态启动报告 Worker；已有报告任务为空，不存在发布兼容迁移。
3. 用受控本地测试数据验证首次锁定、重跑成员不漂移、原帖状态/文本/AI 改变不影响来源、互动按 Run 更新、失败重试、清理与 Word 白名单。
4. 最小人工验证仅创建本地报告、确认来源清单、重跑一次并导出指定版本 Word，核对成员数不变、互动时点可变和限制说明；不得建立 CDP 会话或执行上游读写。
5. 回滚时停止报告 Worker并移除入口；已生成报告按保留策略只读保留供审计，后续数据库迁移遵循发布流程，不删除历史记录。
