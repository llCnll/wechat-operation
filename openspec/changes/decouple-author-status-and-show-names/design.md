## Context

`OriginalPost` 已保存 `author_openid`，`AuthorMuteStatus` 以 `(openid, source_appid)` 投影作者昵称和禁言状态，且固定 IPC 已提供 `POSTS_GET_AUTHOR_DETAIL -> getuserdetail`。禁言维护 Worker 的列表刷新和全量已知作者扫描已调用该接口，但一次性 `AUTHOR_MUTE_STATUS_BACKFILL` 仍逐帖调用 `topicsearchgetdetail`；内容管理的 `MUTE`/`UNMUTE` 也在共用帖子处置流程中以帖子详情做身份预检和写后状态确认。

帖子删除会使帖子详情读取失败，却不应抹除已知作者的独立禁言状态。上游禁言与解除的实际写请求接受运行时 `account_openid`；当前适配器在调用方提供已核验的 `author_openid` 时不再读取帖子详情。当前 `ReviewTask` 与 `OperationAudit` 仍以帖子为审计关联，且屏蔽、沉底、恢复是固有的帖子操作，不能与作者状态读取混为一谈。

内容管理目前没有 `OriginalPost` 级别的作者昵称投影；只在 `AuthorMuteStatus.nick_name` 中保存昵称，导致普通作者和未进入禁言列表的帖子无法显示名称。运行态、日志、任务参数和页面均不得暴露作者 OpenID、认证材料、Cookie、令牌、完整上游响应或二维码目标。

## Goals / Non-Goals

**Goals:**

- 对已知作者，所有作者禁言状态读取、`MUTE`/`UNMUTE` 的状态预检和写后确认均仅以当前游戏范围和 `author_openid` 调用固定作者详情接口，不调用帖子详情。
- 将作者昵称作为 `OriginalPost.author_nick_name` 的最小化显示投影；内容管理以昵称展示作者，缺失时显示明确但不含 OpenID 的未知状态。
- 将一次性历史回填替换为新的版本化任务：优先按已知作者去重读取作者详情以补齐昵称与状态；仅对尚无作者 ID的帖子读取帖子详情以发现身份。
- 明确删除帖缺少本地作者 ID时的安全降级和可审计进度，不伪造身份或禁言结论。
- 保持现有游戏范围、人工确认、写开关、操作幂等键、写结果不明回读语义和帖子审计关联。

**Non-Goals:**

- 不将屏蔽、沉底、恢复等帖子状态操作改为作者操作，也不改变其 `topic_id` 契约。
- 不新增作者搜索、作者枚举、按昵称查询、批量上游禁言或自动写入能力。
- 不以空昵称、删除帖或缺失 OpenID 推断作者未禁言，也不从历史帖子以外的数据源补造作者身份。
- 不重构 `ReviewTask`/`OperationAudit` 为独立作者审计模型；帖子继续作为内容处置和人工审计的本地关联，但不作为作者状态远端读取前提。

## Decisions

### 1. 作者状态拥有独立的固定读取边界

新增/收敛一个内部作者状态读取路径，输入固定为 `ExecutionScope` 和已验证的 `author_openid`，输出只接受 `data.user` 中的昵称、当前游戏禁言截止与全局禁言截止。路径必须校验响应 OpenID 等于请求 OpenID，再调用已有投影服务更新 `AuthorMuteStatus`；不匹配、字段缺失或来源失败不得更新旧状态。

`MUTE`/`UNMUTE` 从共用帖子详情预检中分支：从 `OriginalPost.author_openid` 获取已保存身份，先通过该读取路径取得状态；上游写入仍沿用固定 `POSTS_OPERATION`、人工确认、操作 ID和既有开关，并将已验证身份放入 payload，避免适配器回退读取帖子详情。写后最多四次的受限回读改为作者详情。`ReviewTask.post` 继续用于审计、原因和内容上下文，不能参与远端作者状态读取。

采用此方案是因为用户详情接口正是按作者读取且写接口接受同一运行时身份；继续把帖子详情作为作者状态来源会在帖子删除时制造无关失败。替代方案“删除帖子后继续重试帖子详情”不能恢复作者状态；替代方案“直接把 OpenID 持久化到审计或任务参数”违反最小化与现有数据边界，故不采用。

### 2. 为原创帖保存昵称投影，而不是让页面联表或实时读取

给 `OriginalPost` 增加可空/空字符串默认的 `author_nick_name`。每次从帖子详情或作者详情成功确认作者时，投影服务原子更新当前帖子身份和昵称；作者详情成功时，更新同一 `source_appid + author_openid` 下昵称为空或过期的关联帖子。页面只读取该字段，不在 Web 请求中调用固定 IPC，也不以 `AuthorMuteStatus` 的存在作为显示前提。

昵称是运营识别所需的最小显示字段，放在帖子投影可使普通作者同样可见。替代方案“页面从 `AuthorMuteStatus` 联表回退昵称”会遗漏未禁言作者，并使展示依赖禁言管理记录；替代方案“页面实时查询作者详情”违反 Web 不执行会话生命周期/来源读取的边界，故不采用。

### 3. 历史回填按身份发现与作者详情补齐两阶段处理

一次性回填使用新的任务类型 `AUTHOR_MUTE_STATUS_BACKFILL_V2`、显式版本化幂等键和检查点模式，以独立执行昵称补齐。对作者状态回填任务族，人工补采 Worker 只注册 V2 handler，不认领 V1 类型任务；`MANUAL_INGEST_WINDOW`、`METRICS_REFRESH_WINDOW`、`INGEST_WINDOW` 等既有人工补采任务范围保持不变。任务按当前游戏的原创帖稳定游标处理：

1. 帖子已有 `author_openid` 时，只对该作者执行一次 `get_author_detail`，校验身份后更新作者状态和同游戏关联帖昵称。
2. 帖子缺少 `author_openid` 时，才调用帖子详情发现 `creater.openid` 与昵称；成功后立即投影。该帖子若已被删除，则记录脱敏跳过计数并推进游标。
3. 任务检查点仅保存版本、范围、游标、成功/失败/跳过数量与脱敏原因类别；不得保存 OpenID、昵称、原始响应或认证信息。

本 change 不兼容、不迁移或恢复 V1 回填任务，部署前必须确认不存在非终态 V1 Job；实现不得为旧 checkpoint 增加运行时分支。V1 类型不注册到作者状态回填 handler，因此新部署不会认领或恢复遗留 V1 Job。新版本任务单独入队并沿用仅人工补采 Worker 消费、非调度、零自动重试的边界。采用两阶段而非纯作者详情是因为没有 OpenID 的历史记录无法调用作者接口。

### 4. 删除帖与缺失身份的失败语义保持区分

已知 OpenID 的作者无论关联帖子是否删除，仍可通过作者详情刷新；帖子删除状态不得阻断该调用。只有“帖子删除且 OpenID 为空”才是不可恢复的身份缺口，任务记录 `MISSING_AUTHOR_IDENTITY` 类别并继续。禁言状态页面将其展示为未同步/未知，不创建“已确认未禁言”投影。

这比将所有 `SourceBusinessDeletedError` 一律视为作者状态失败更准确；也避免将一次读取失败伪装为普通未禁言作者。

### 5. 先完成只读身份一致性验证，才实现作者路径承载写前后核验

实现 `MUTE`/`UNMUTE` 作者核验路径前，必须在受控已登录会话对明确授权的测试作者完成只读演练：比较作者详情与对应帖子详情的 OpenID，并记录两者一致或不一致的脱敏结论。既有受控写入调研已验证帖子详情 `creater.openid` 可作为禁言适配器的 `account_openid`；本次只读演练只验证作者详情是否返回同一身份，不把该推论表述为新的写接口验证。演练不发送禁言或解除写请求。验证失败或未执行时，本 change 不得实现或发布作者路径的禁言预检与写后回读。通过后，测试必须覆盖：`getuserdetail.data.user.openid` 与已请求 OpenID 一致才可写入投影；`MUTE`/`UNMUTE` 提供该身份时适配器不读取帖子详情；帖子删除后的已知作者状态预检与回读仍成功。真实写操作仍只按现有独立授权和人工二次确认流程执行。

## Risks / Trade-offs

- [用户详情 OpenID 与禁言写接口身份语义不一致] → 在实现作者禁言核验路径前完成受控只读一致性演练；未验证或失败时停止本 change 的该部分实现，不发布替换路径。
- [历史任务对同一作者重复读取] → 以当前游戏和已保存 OpenID 去重，成功后更新同游戏关联帖子；检查点保证中断后不丢失已推进进度。
- [昵称被上游改名后本地过期] → 作者详情成功时更新所有同游戏关联帖子；不在页面实时读取，接受两次同步间的显示延迟。
- [删除帖没有已知身份] → 记录脱敏跳过并继续；不得猜测身份或状态。
- [帖子审计关联与作者读取边界混淆] → 保留 `ReviewTask.post` 仅作本地审计上下文，并在测试中断言作者读取不调用 `get_post_metrics`。

## Migration Plan

1. 增加 `OriginalPost.author_nick_name` 的空默认迁移，发布时不回填或阻塞现有数据。
2. 先实现作者详情投影、昵称展示和读取路径的单元测试；保持帖子操作和开关语义不变。
3. 确认没有非终态 V1 回填 Job 后，以新版本化键入队一次性历史回填，由人工补采 Worker 受控执行；在不含真实身份信息的测试数据库验证断点、删除帖跳过和昵称更新。
4. 回滚时回退代码并停止新回填 Job；新增昵称列可保留且不参与旧版本逻辑。不得删除已有状态或手工修改检查点。

## Open Questions

- 无。受控只读身份一致性演练是实现作者禁言核验路径的前置门槛，验证失败时停止该路径的实现并以新的 OpenSpec 结论处理。
