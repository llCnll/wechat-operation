# 跨模块数据归属

本文仅保留跨模块数据的真相源和关联边界，不重复字段清单。具体 schema 由 Django models 和 migrations 定义。

| 数据 | 唯一所有者 | 跨模块使用边界 |
| --- | --- | --- |
| 已授权游戏目录与当前操作范围 | posts | 目录来自授权同步；当前范围须显式选择。首次来源访问时任务冻结范围。 |
| 候选帖、原创帖与作者身份投影 | posts | 原创帖是工作台主体；作者状态按作者和游戏独立维护。评论正文不保存。 |
| OCR、评估、审核、回复草案与处置审计 | reviews | 模型建议不等同授权；自动写入留不可变快照并进入人工复审。 |
| 异步任务、生产者配置、逻辑槽与 checkpoint | jobs | Scheduler 只创建任务；消费者按任务类型隔离。冻结范围不随当前游戏切换改写。 |
| 来源指标快照、报告输入和 Run | reporting | 指标按来源和业务时间保存；报告锁定来源、输入和算法版本。 |
| 会话 lease、浏览器 target 与认证材料 | config 会话服务内存 | 认证材料不持久化；数据库只保存不含秘密的运行状态投影。 |
| 服务 desired、实例租约与进程登记 | service_supervisor | 期望状态与实际观测分离；只回收可证明归属当前/旧实例的进程。 |

本页不承担表结构字典；行为约束以对应模块规格为准。


## 关键取舍

### 业务数据由所属模块维护，跨模块只共享最小投影

- 背景：帖子、审核、报告和后台任务各自有不同生命周期；集中建立一个跨业务万能模型会混合权限和清理语义。
- 决策：模块分别拥有帖子/作者、审核/处置、任务、指标/报告和运行状态；关联通过稳定业务标识和受控投影完成。
- 否决方案：跨模块重复保存整份上游响应、重复维护作者/帖子状态，或由页面联表推断业务状态。
- 约束：数据写入经过所属模块服务；敏感认证上下文不进入持久化业务数据；模型变更以所属 Django migration 和对应主规格评审。
- 重新评估：新增数据域时先确认唯一 owner、保留期限、删除语义和必要投影后，再决定是否新建模型或模块。
