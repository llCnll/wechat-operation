# 游戏圈会话恢复

本手册只写运营人员可重复执行的步骤；会话有效条件和失败状态以 [config 模块规格](../../../openspec/specs/config/spec.md)为准。

## 首次连接或扫码恢复

1. 通过 Supervisor 启动本项目服务，并确认系统配置页可用。
2. 确认已同步并选择当前操作游戏。
3. 从系统配置页打开唯一的受控会话页；仅在页面要求扫码时完成扫码，不重复打开登录入口。
4. 等待会话状态恢复。外层登录成功后，如当前游戏 Frame 仍未就绪，再使用页面的“建立当前游戏 Frame”操作。
5. 使用只读的帖子或指标读取确认来源可用后，再恢复待处理任务。

不要使用普通浏览器、手动新开站点 tab 或直接访问 CDP 端口替代受控会话流程。不要把 Cookie、token、完整认证 URL、target ID 或 capability 复制到工单、文档或日志。

## 来源请求失败

- 显示需要登录：按上述步骤完成扫码，等状态确认后重新发起读取。
- 显示 Frame 未就绪：先建立当前操作游戏 Frame，再重新发起只读读取。
- 传输、契约或权限失败：查看对应任务的脱敏错误分类，按模块规格处理；不得把非认证错误当作扫码问题反复刷新。
- 已确认的上游写操作若结果待回读确认，先核验审计与平台当前状态；不得在恢复会话后自动重放。

## 密钥与配置

启动期密钥和端口从 runtime/.env 读取；管理台中的 AI/OCR 与写操作开关按对应配置入口管理。密钥只写入，不回显。更换运行配置后按系统提示重启对应服务，不编辑或复制会话运行态文件。

## 验证边界

新环境优先执行只读验证。需要跨平台 Supervisor、Chrome owner 替换或上游写入核验时，遵循 [发布环境核验清单](../../01-platform/runbooks/release-verification.md)，使用明确授权的测试账号并记录本次执行结果；本手册不代表这些真实环境验证已通过。
