# 微信小游戏圈每日指标接口调研

调研日期：2026-07-20
调研范围：微信公众平台插件“内容粉丝数据”和“游戏圈粉丝数据”。
接口类型：`crud_read`（已授权受控浏览器会话内的私有只读查询）。

## 1. 结论

“每日 `07:00` 更新”不等同于“只能读取昨日快照”。当前页面前端和受控会话验证表明，至少部分每日指标支持按历史日期范围查询：

| 数据域 | 页面更新口径 | 历史查询能力 | 证据状态 |
| --- | --- | --- | --- |
| 内容粉丝数据 | 每日 `07:00` | 详情调用带 `begin_time`、`end_time`，默认范围为近 3 个月至昨日，单页 `per_page=366` | 当前页面前端已验证；当前运营账号返回无权限，尚未取得成功样本。 |
| 游戏圈粉丝数据 | 每日 `07:00` | 详情调用带 `start_ds`、`end_ds`，支持日期快捷范围或自定义区间，单页 `per_page=366` | 已在当前授权会话成功查询 10 天历史范围。 |
| 运营效果数据 | 每周一 `17:00` | 周详情接口带 `ds_begin`、`ds_end` | 见[首页指标接口调研](wechat-game-circle-home-metrics-research.md)。 |

因此持久化策略必须按**字段/数据域**建模：可查历史的指标先受控回填，再按日增量复核；因权限或接口限制不能回填的指标才仅从当天起做 T+1 快照。不得用“每日更新”推断接口不支持历史。

## 2. 公共认证与安全边界

两项查询均在 `gamemp.weixin.qq.com` 的受控游戏圈 iframe 内运行，使用运行时 `binduseridentity` 产生的临时 token、`auth_type=4` 和当前登录 Cookie。令牌、Cookie、完整认证 URL、运营者或作者身份标识不得持久化、打印或写入任务参数。

调用仅限当前运营账号可管理的游戏和页面授权的数据域。权限错误不能伪造空数据、不能降级为历史 token 重放，也不能绕过页面授权。

## 3. 游戏圈粉丝历史详情接口

### 基本信息

```text
POST /cgi-bin/gameopenmpwap/cfcommcgi/spacexgamemp_datacenter_getgroupuserdetaildata
Host: gamemp.weixin.qq.com
```

### 请求体

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `type` | integer | 是 | `1`：游戏圈粉丝数；`2`：活跃粉丝留存。 |
| `start_ds` | integer | 是 | 起始日，`YYYYMMDD`。 |
| `end_ds` | integer | 是 | 结束日，`YYYYMMDD`。 |
| `desc_order` | boolean | 是 | 当前页面传 `false`。 |
| `cur_page` | integer | 是 | 零基页码，当前页面传 `0`。 |
| `per_page` | integer | 是 | 当前页面传 `366`；服务端最大范围未验证。 |

最小示例（不含认证参数）：

```json
{
  "type": 1,
  "start_ds": 20260710,
  "end_ds": 20260719,
  "desc_order": false,
  "cur_page": 0,
  "per_page": 10
}
```

### 已验证响应字段

`type=1` 在当前授权会话返回 HTTP `200`、`errcode=0` 和 10 条历史日记录；每条记录至少含：

| 字段 | 页面标签 | 说明 |
| --- | --- | --- |
| `ds` | 日期 | 指标归属日。 |
| `total_user` | 游戏圈粉丝总数 | 当日存量。 |
| `add_user` | 新加圈粉丝数 | 当日新增。 |
| `del_user` | 退圈用户数 | 当日取消关注。 |

`type=2` 的页面用于“活跃粉丝留存”。前端读取 `follower_quanzi_rt{1,2,3,4,5,6,7,14,30}_dau`；成功响应样本及空值语义仍待单独验证。

## 4. 内容粉丝历史详情接口

### 基本信息

```text
POST /cgi-bin/gameopenmpwap/cfcommcgi/spacexgamemp_dataauthor_getauthordetaildata
Host: gamemp.weixin.qq.com
```

### 请求体

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `type` | integer | 是 | `1`：帖子消费；`2`：粉丝关注；`3`：发布帖子；`4`：帖子互动。 |
| `begin_time` | integer | 是 | 起始日，`YYYYMMDD`。 |
| `end_time` | integer | 是 | 结束日，`YYYYMMDD`。 |
| `cur_page` | integer | 是 | 零基页码，当前页面传 `0`。 |
| `per_page` | integer | 是 | 当前页面传 `366`。 |
| `wx_account` | string | 条件必填 | 仅选择 UGC 认证账号时传入。属于账号标识，不应默认持久化。 |
| `author_id` | string | 条件必填 | 仅选择 PGC 认证账号时传入。属于账号标识，不应默认持久化。 |

页面默认聚合全部认证账号时不传 `wx_account`、`author_id`，默认查询近 3 个月至昨日。按 `type` 已观察到的详情字段如下：

| `type` | 字段 | 页面标签 |
| --- | --- | --- |
| `1` 帖子消费 | `expose_cnt`、`share_cnt` | 当日帖子浏览量、当日帖子分享数 |
| `2` 粉丝关注 | `fans_cnt`、`today_fans_cnt`、`active_fans_cnt`、`active_fans_per` | 粉丝总数、日新增粉丝数、活跃粉丝数、活跃粉丝占比 |
| `3` 发布帖子 | `publish_pv`、`pic_publish_pv`、`vid_publish_pv` | 发布帖子总数、新增图文帖子数、新增视频帖子数 |
| `4` 帖子互动 | `comment_succ_cnt`、`like_cnt` | 当日评论数、当日点赞数 |

当前授权会话在不传作者标识的 `type=2` 查询中返回 HTTP `200`、`errcode=-10000401`、`errmsg=无权限访问`。这表明接口路径可达但当前账号未获该数据域权限；它不是“无历史数据”的结论。实现必须将此类结果标记为权限不可用，不创建零值快照。

## 5. 建议的保存策略（待实现规格确认）

首期范围固定为已验证可管理的“城主别慌张”（`wx6d2454a8afcd9706`）。不查询其他游戏；内容粉丝仅保存该游戏下“全部认证账号”的聚合结果，不保存或分组展示 `wx_account`、`author_id` 等账号标识。

1. 对已确认可回填的范围接口，首次运行按受控日期块补齐历史；每次只保存业务需要的聚合数值，不保存原始响应。
2. 每日北京时间 `07:30` 后采集前一个自然日，为上游标称 `07:00` 更新预留稳定窗口；采用短重试并复核最近若干日，而不是只写一次后永久冻结。
3. 每周一北京时间 `17:30` 后同步运营效果周数据，为上游标称 `17:00` 更新预留稳定窗口；若周详情支持范围查询，使用幂等补齐和短窗口复核处理上游修订。
4. 每条本地快照至少区分 `source`、`appid`、指标归属日/周、聚合范围、同步时间与指标值；以稳定业务键幂等更新。不得以采集时间替代指标归属日。
5. 作者维度的内容粉丝数据可能需要保存 `wx_account` 或 `author_id`。它们属于账户标识，默认仅保存“全部认证账号”聚合；是否保存分账号维度须由运营负责人明确确认后再设计最小化和保留期。

### 登录失效与延后补拉

当前受控 Chrome 登录态每日约 `04:00` 失效，而运营人员通常在约 `09:30` 扫码恢复。日指标任务应在每日 `07:30` 后创建，并将“昨日”的业务日期写入任务参数；不得因为实际执行晚于 `07:30` 而改为采集当天。

在登录失效期间，Worker 先检测 CDP/插件登录态。未登录、token 绑定失败或插件页不可用时，任务应转为“等待登录态”并延后检查，不增加失败重试计数、不写零值、也不尝试自动登录。运营人员扫码后，下一次轮询自动恢复同一任务；若多日未登录，历史任务按各自锁定的业务日期依次补拉。所有读取仍在当前受控 iframe 内使用临时认证上下文完成。

## 6. 最小验证

- 在受控 Chrome 中确认 CDP 和登录态有效；不使用保存的 token 或 Cookie。
- 游戏圈粉丝 `type=1`：查询不少于两个历史自然日，确认 `errcode=0`、`data.list` 为数组，且每条含 `ds`、`total_user`、`add_user`、`del_user`。
- 内容粉丝：先验证数据域权限；获得授权后，以一个短历史范围验证每个启用的 `type` 的字段结构与空值语义。权限失败必须以脱敏失败状态结束。
- 落库验证：同一稳定业务键重复同步不得重复创建记录；上游修订值应按既定规则更新并保留最新同步时间。
