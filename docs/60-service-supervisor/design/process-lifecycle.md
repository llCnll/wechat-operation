# 进程生命周期与租约

原文决策来源：commit c9299f168b7566f9d188017acc16e08f8ad6b43b，openspec/changes/archive/2026-07-26-stabilize-supervisor-process-lifecycle/design.md、2026-07-28-harden-supervisor-lease-renewal/design.md、2026-08-02-harden-supervisor-lifecycle-observability/design.md。当前可验收行为以 service_supervisor 模块规格为准。

## 关键取舍

### 期望状态与进程观测分开

- 背景：进程崩溃、租约超时与运营人员显式停用是不同事件。
- 决策：Supervisor 保存期望状态；独立记录服务状态和实例心跳，恢复逻辑按 desired 调和。
- 否决方案：进程退出即把 desired 设为停止，或只靠进程存在判断服务健康。
- 约束：异常退出不能清除启用意图；启动替代实例前需核实旧实例退出与职责锁释放。
- 重新评估：部署从单机单 Supervisor 变成集群编排后，重新定义期望状态的所有者与租约一致性。

### 进程回收只针对可验证登记项

- 背景：PID 可能复用，系统中也可能存在用户自己启动的同类程序。
- 决策：服务启动后登记实例身份；回收时联合 PID、创建时间、完整 argv 和工作目录核验。
- 否决方案：扫描进程名、端口或命令子串后批量终止。
- 约束：无法确认归属时跳过，并通过租约守卫使旧服务自行退出。
- 重新评估：如果引入操作系统服务管理器，应以其服务身份替代自建登记，不放宽身份核验。

### Chrome 健康以 generation 而非 PID 判断

- 背景：浏览器启动器 PID 交接不必然意味着 Chrome 会话退出。
- 决策：结合固定 loopback CDP 端点与 browser generation 判断健康；仅在明确 owner 替换时回收该 owner 创建的资源。
- 否决方案：PID 消失就重启 Chrome，或扫描并接管所有相似浏览器页。
- 约束：专用端口保持固定；未知 target 不接管、不关闭。
- 重新评估：改用受管浏览器 API 或容器隔离后，重新验证进程和页面所有权。

### 租约续约失败按存储故障处理

- 背景：Windows 杀毒软件、备份或文件共享锁可能短时阻止原子替换。
- 决策：有界退避重试；续租暂时失败时跳过当轮调和并记录脱敏诊断，不延长旧租约，也不立即全局关闭。
- 否决方案：直接覆盖状态文件、假定租约仍有效或短暂失败即强杀所有服务。
- 约束：最终租约过期后 Web/Worker 仍须退出；重试不得掩盖持续故障。
- 重新评估：运行态改用具备原子租约和一致性语义的服务时，重新制定失败策略。


### 生命周期诊断只暴露固定类别和可审计摘要

- 背景：只保存当前状态难以解释恢复失败，但暴露 PID、target ID 或控制令牌会泄漏可用于接管的运行态身份。
- 决策：用有界生命周期事件记录固定事件/原因类别；会话服务只发布 target 操作摘要，Supervisor 通过既有受认证控制通道提供只读投影。
- 否决方案：在日志中输出完整运行态 JSON、target 身份或原始错误载荷。
- 约束：诊断项有长度和数量上限，严格脱敏；事件不可替代服务当前状态。
- 重新评估：新增诊断字段前检查其是否可关联到本机进程、认证材料或浏览器 target，并明确保留期限。
