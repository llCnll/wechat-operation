# 指标快照与舆情报告 Run

原文决策来源：commit c9299f168b7566f9d188017acc16e08f8ad6b43b，openspec/changes/archive/2026-07-21-add-game-circle-metric-snapshots/design.md、2026-07-27-add-async-public-opinion-reports/design.md。

## 关键取舍

### 来源指标保持各自业务键和日期口径

- 背景：首页概览、日指标和内容分析来自不同接口，更新时间和聚合口径不完全一致。
- 决策：按来源、范围与业务时间保存白名单快照，不构造跨来源总分。
- 否决方案：把不同来源合并成综合指标，或用缺失数据补零。
- 约束：图表保留来源口径；未验证日期和不完整业务日不能显示为真实零值。
- 重新评估：上游提供统一定义、可比基准和历史一致性保证后，再评估是否合并展示。

### 报告输入与算法版本在创建时冻结

- 背景：帖子、身份、互动、AI 结论会随时间变化，单条可变报告无法解释历史差异。
- 决策：报告锁定范围和来源集合；每次计算、重跑生成独立 Run 并记录算法版本。
- 否决方案：覆盖同一报告的旧结果，或展示时读取最新业务数据。
- 约束：模型结论只消费锁定输入；来源不可用和模型失败需明确降级，不改变已完成 Run。
- 重新评估：只有明确审计需求和迁移方案能保留旧运行历史时，才考虑变更版本模型。
